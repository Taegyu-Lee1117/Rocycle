**작성일** 2026-09-10

# 제1부 · 사용자(운영자) 교육자료

**대상**: 시스템을 조작해 재활용품을 분류하는 작업자
**목표**: 안전하게 시스템을 운용하고, 이상 상황을 알아채 대응한다

---

## 1. 시스템이 하는 일

**컨베이어로 흘러오는 재활용품을 카메라가 인식하고, 로봇 팔이
집어서 종류별 통에 넣습니다.**

**로봇이 판단할 수 없는 것은 억지로 처리하지 않습니다.**

```
사람이 처리해야 하는 것    사람에게 직접 건넵니다
판단이 불확실한 것         확인 필요 통으로 보냅니다
인식되지 않는 것           손대지 않고 흘려보냅니다
```

---

## 2. 인식하는 물체

**모델은 여섯 가지를 학습했지만, 실제 운영(통 배정)에 쓰이는
건 다섯 가지입니다.**

| 물체 | 들어가는 곳 |
|---|---|
| 캔 | 캔 통 (내용물이 있으면 확인 필요 통) |
| 건전지 | 건전지 통 |
| 라벨 붙은 페트병 | 사람에게 전달 (라벨 제거 필요) |
| 플라스틱 뚜껑·용기 | 플라스틱 통 |
| 비닐 | 확인 필요 통 |

**종이 상자는 운영 대상에서 제외됩니다.** 모델은 종이 상자를
학습했지만, 화면상 좌우 위치에 따라 페트병과 종이 상자 양쪽으로
100% 갈리는(신뢰도 0.92~0.95, 양쪽 다 확신) 결정경계 문제가
있어 조명·자세와 무관하게 통제가 안 됩니다. 그래서 종이 상자용
통 자체를 운영하지 않습니다 — 종이 상자를 투입하면 결과를
예측할 수 없으니 투입하지 마세요.

**그 밖의(위 다섯 가지·종이 상자를 뺀) 물체는 로봇이 손대지
않고 벨트 끝으로 흘러갑니다.**
이는 고장이 아니라 의도된 동작입니다.

---

## 3. 물체를 올리는 방법

**세 가지를 지켜주세요.**

### 3-1. 표시된 위치에 놓습니다

**벨트에 표시된 가로 위치 안에 놓아야 합니다.**

**위치가 벗어나면 인식이 달라질 수 있습니다.**

### 3-2. 캔은 벨트 방향과 나란히 놓습니다

**비스듬히 놓으면 인식되지 않습니다.**

```
✓  벨트가 흐르는 방향과 캔의 긴 축을 나란히
✗  비스듬하게, 또는 가로질러서
```

### 3-3. 간격을 둡니다

**앞 물체가 처리될 공간이 있어야 합니다.**

**한 번에 세 개 정도가 적당합니다. 자리가 나면 다음 물체를
올립니다.**

---

## 4. 조작

### 4-1. 화면 버튼

| 버튼 | 동작 |
|---|---|
| 시작 | 컨베이어 가동, 분류 시작 |
| 일시정지 | 현재 물체를 마친 뒤 정지 |
| 재개 | 정지 상태에서 다시 시작 |
| 종료 | 현재 물체를 마친 뒤 종료하고 결과 보고 |

**일시정지와 종료는 즉시 멈추지 않습니다.** 물체를 든 채로
멈추면 위험하기 때문에, 지금 하던 것을 마친 뒤 반영됩니다.

### 4-2. 음성 명령

**시작과 종료를 음성으로도 할 수 있습니다.**

**다만 음성은 항상 대기하지 않습니다.** 확실하게 하려면 화면
버튼을 사용하세요.

### 4-3. 비상 정지

**위급할 때는 물리 비상정지 버튼을 누릅니다.**

**화면의 비상정지 버튼은 컨베이어를 즉시 멈추지만, 로봇 정지는
보장되지 않습니다.**

---

## 5. 화면 보는 법

### 5-1. 상단

| 표시 | 의미 |
|---|---|
| RUNNING | 작업 중 |
| IDLE | 대기 중 |
| PAUSED | 일시정지 |
| STOPPING | 종료 처리 중 |

**옆에 경과 시간이 나옵니다.** 한 물체 처리에 20초쯤 걸리므로,
화면이 멈춘 것처럼 보여도 정상입니다.

**경과 시간이 40초를 넘으면 뭔가 걸린 것일 수 있습니다.**

### 5-2. 연결 상태

**점 다섯 개가 카메라·로봇·컨베이어·음성 입력·음성 출력의
연결을 나타냅니다.**

**회색이면 그 장치가 연결되지 않은 것입니다.**

### 5-3. 처리 현황

**통별로 몇 개가 들어갔는지 보여줍니다.**

### 5-4. 알림

**아래쪽에 최근 알림이 나옵니다.**

```
빨강   오류
노랑   경고
회색   정보
```

---

## 6. 사람에게 전달받기

**라벨 붙은 페트병은 로봇이 사람에게 건넵니다.**

```
1. 로봇이 물체를 들어 올려 앞으로 내밉니다
2. "라벨을 제거해야 합니다"라는 안내가 나옵니다
3. 물체를 잡고 당깁니다
4. 로봇이 놓아줍니다
```

**당기는 요령**

```
✓  수평 방향으로 확실하게 당깁니다
✗  아주 천천히 조금씩 당기면 인식되지 않습니다
```

**15초 동안 받지 않으면 로봇이 확인 필요 통으로 옮깁니다.**
이것도 정상 동작입니다.

---

## 7. 이럴 때는 이렇게

| 상황 | 판단 | 조치 |
|---|---|---|
| 물체가 그냥 지나감 | 인식 대상이 아님 | 정상. 조치 불필요 |
| 캔이 인식 안 됨 | 방향이 비스듬함 | 나란히 놓아 다시 투입 |
| 빈 물체가 확인 필요 통으로 | 무게 측정 오차 | 관리자에게 알림 |
| 컨베이어가 멈춤 | 안전 정지 | 화면 알림 확인 |
| 로봇이 물체를 든 채 멈춤 | 이상 상황 | 관리자 호출 |
| 화면이 안 뜸 | 서버 미기동 | 관리자 호출 |

---

## 8. 안전 수칙

```
로봇이 움직이는 동안 작업 영역에 들어가지 않습니다
물체를 받을 때만 지정된 위치에서 받습니다
비상정지 버튼이 손에 닿는 곳에 있는지 확인합니다
로봇이 멈춘 것처럼 보여도 작업 중일 수 있습니다
```

# 제2부 · 관리자 교육자료

**대상**: 시스템 설정을 변경하고 문제를 해결하는 담당자
**목표**: 시스템 구조를 이해하고 설정·점검·복구를 수행한다

---

## 1. 시스템 구조

### 1-1. 처리 흐름

```
카메라 → 검출 → 추적 → 예측 → 파지 → 계량 → 판정 → 배치
```

**각 단계가 별도의 판단을 수행하며, 어느 단계에서든 실패하면
안전한 경로로 빠진다.**

### 1-2. 노드 구성

| 노드 | 역할 |
|---|---|
| 검출 노드 | 카메라 영상에서 물체를 찾음 (컨테이너로 분리) |
| 제어 노드 | 추적·예측·파지·판정·배치 전체 담당 |
| 컨베이어 노드 | 시리얼 통신으로 벨트 제어 |
| 로봇 드라이버 | 로봇 모션·힘 제어 서비스 제공 |
| 그리퍼 노드 | 그리퍼 개폐 제어 |

**검출을 분리한 이유**: 추론이 오래 걸려 같은 프로세스에서
돌리면 로봇 제어가 멈춘다.

---

## 2. 기동과 종료

### 2-1. [최우선] 로봇 시작 자세

**로봇을 홈 자세로 보내고 시작하지 않는다.**

**이유**: 무게 기준값을 현재 자세에서 측정하므로, 자세가 다르면
약 200g의 오차가 생긴다.

**증상이 조용하다**: 로그에는 정상 처리로 기록된다.

**확인 방법**: 빈 캔 하나를 올려 캔 통으로 가는지 본다.

**이 확인은 재부팅·비상정지 복구·수동 조작 후에 매번 수행한다.**

### 2-2. 기동 순서

```
1. 로봇 스택 (로봇 + 그리퍼)
2. 카메라 드라이버 2종
3. 검출 컨테이너
4. 제어 노드
5. 컨베이어 노드
6. 음성 노드
```

**화면(rosbridge/web_video_server)과 데이터베이스는 관제 PC에서
띄우지 않는다 — 별도 PC에서 동작한다.** 관제PC에서 위 1~6번을
다 띄워도 이 PC엔 외부로 열린 포트가 없는 게 정상이다. 화면이
안 뜨면 관제PC를 의심하기 전에 **먼저 이쪽(로봇/카메라/검출)
이 규격대로 토픽을 내보내는지 `ros2 topic echo`로 확인**하고,
정상이면 화면 쪽 PC/코드 문제이니 그쪽 담당자에게 넘길 것 —
관제PC 쪽 코드를 직접 고치지 말 것.

### 2-3. 기동 확인

```
ros2 node list                              노드 목록
ros2 topic hz /image_raw                    약 7.5Hz
ros2 topic hz /recycle_detection/detections 약 7.4Hz
ros2 topic echo /ui/state --once            상태 확인
```

## 3. 설정 변경

### 3-1. 설정 파일

| 파일 | 담는 내용 |
|---|---|
| `gripper_profiles.yaml` | 품목별 파지력·대기·깊이·보정 |
| `item_routing.yaml` | 품목별 목적지·무게 조건 |
| `bin_teach_points.py` | 통 좌표 |
| `motion_timing.yaml` | 이동 속도, 도달 한계 |

**코드에 품목명을 직접 쓰지 않는다.** 새 품목은 설정 추가만으로
동작해야 한다.

**참고**: 저장소에는 `vision.yaml`(검출 신뢰도, 화면 여백 설정
용도로 만들어짐)도 있지만, **관제 PC 실행 트리에는 존재하지
않아 현재 운영에서 쓰이지 않는다.** 이 파일을 고쳐도 실제 동작은
바뀌지 않으니 혼동하지 말 것 — 검출 신뢰도 등을 조정하려면
실제로 쓰이는 설정 파일(위 표)을 확인할 것.

### 3-2. 증상별 조정

| 증상 | 조정 |
|---|---|
| 물체가 찌그러진다 | 파지력 하향 |
| 물체가 미끄러진다 | 파지력 상향 |
| 물체 뒤에 착지 | 예측 보정값 증가 |
| 물체 앞에 착지 | 예측 보정값 감소 |
| 물체를 누른다 | 하강 깊이 감소 |
| 헛잡는다 | 하강 깊이 증가 |

### 3-3. 조정 시 원칙

```
한 번에 하나만 바꾼다
바꾸기 전 값을 기록한다
바꾼 뒤 여러 번 시험한다
같은 품목 안에 형태가 다양하면 가장 취약한 것을 기준으로 한다
```

## 4. 주요 판정 원리

### 4-1. 예측 파지

**로봇이 도착할 시점의 물체 위치를 미리 계산한다.**

```
예측 위치 = 현재 위치 + 속도 × (준비 + 이동 + 하강 시간)
```

**준비 동작을 추가할 때는 반드시 예측 계산에 포함시킨다.**
그렇지 않으면 그 시간만큼 빗나간다.

### 4-2. 무게 판정

```
파지 전 무게를 잰다
파지 후 고정된 자세로 이동해 다시 잰다
차이가 순 무게다
```

**두 측정이 같은 자세여야 한다.** 자세가 다르면 중력 보정이
어긋난다.

**힘 센서에 주기 약 27초, 진폭 ±45g의 진동이 있다.**
**따라서 정밀 계량이 아니라 유무 판별로만 쓴다.**

**판정 대상은 50g 미만 또는 350g 초과여야 한다.**

### 4-3. 핸드오버 판정

**사람의 당김과 중력 처짐을 구분한다.**

| | 속도 | 방향 |
|---|---|---|
| 당김 | 6~12mm/s | 수평 |
| 처짐 | 1mm/s 이하 | 하향 |

**두 조건을 모두 만족해야 놓는다.**

```
수평 속도 3.0mm/s 이상, 연속 2회
하향 제외 변위 7mm 이상
```

### 4-4. 안전 정지

**정지 사유를 집합으로 관리한다.** 모든 사유가 풀려야 재가동된다.

**120초가 지나도 안 풀리면 강제 재가동하고 그 물체는 포기한다.**

## 5. 문제 해결

### 5-1. 인식 문제

| 확인 순서 | 내용 |
|---|---|
| 1 | 학습 대상 6종인가 |
| 2 | 벨트 방향과 나란한가 |
| 3 | 표시 위치 안에 있는가 |
| 4 | 화면 가장자리에 걸쳤는가 |
| 5 | 투명한 재질인가 |
| 6 | 검출 토픽이 발행되는가 |

### 5-2. 파지 문제

**예측 조정 전에 확인할 것**

```
준비 동작이 예측 계산 이후에 추가되지 않았는가
좌표 정확도가 유지되는가
```

### 5-3. 무게 문제

**대부분 시작 자세 문제다.** 2-1절 확인 사이클을 먼저 수행한다.

### 5-4. 로봇이 물체를 든 채 멈춤

```
1. 그리퍼 개방 명령으로 회수
2. 또는 티치 펜던트로 수동 회수
3. 노드 재시작
4. 시작 자세 확인 사이클
```

---

## 6. 모델 교체

**모델을 바꾸면 클래스 목록이 달라질 수 있다.**

```
1. 새 모델의 클래스 목록 확인
2. 파지 설정에 모든 클래스가 있는지 확인
3. 라우팅 설정에 모든 클래스가 있는지 확인
4. 전 품목 검출·분류 재확인
```

**설정에 없는 클래스가 들어오면 파지 도중 예외가 발생한다.**

**그리고 기존 클래스의 동작도 달라질 수 있다.** 신뢰도 분포와
오분류 패턴이 변한다.

## 8. 알아둘 함정

| 항목 | 내용 |
|---|---|
| 그리퍼 닫기 | 명령이 반환돼도 동작이 안 끝났다. 대기 시간을 지킨다 |
| 파지력 유지 | 한 번 설정하면 유지된다. 매번 명시적으로 설정한다 |
| 이동 성공 반환 | 성공을 반환해도 안 움직인 경우가 있다. 좌표를 확인한다 |
| 배치 시퀀스 | 통 상공에서 수직으로만 오르내린다. 대각선은 통을 넘어뜨린다 |
| 임시 조치 기록 | 무엇을 우회했는지, 원래 요구가 뭔지, 언제 재검토할지를 함께 적는다 |

## 9. 판단이 필요할 때의 원칙

**본 시스템은 아래 원칙으로 만들어졌다. 설정을 바꿀 때도
같은 원칙을 적용한다.**

```
분류 결과를 안전 게이트로 쓰지 않는다
  비전은 틀릴 수 있다. 사람에게 건네는 판단은 물리량으로 한다

판단할 수 없으면 판단하지 않는다
  억지로 분류하는 것보다 확인 필요 통으로 보내는 것이 낫다

검증이 실제 조건을 재현해야 한다
  실제와 다른 조건으로 확인하면 결론이 뒤집힌다

임시 조치는 반드시 기록한다
  기록하지 않으면 정식 절차로 굳어진다
```
