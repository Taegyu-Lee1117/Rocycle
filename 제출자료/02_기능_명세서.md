## 1. 시스템 구성

### 1-1. 코드 저장소 구성

| 구분 | 위치 | 내용 |
|---|---|---|
| 운영 코드 | 저장소 `main` 브랜치 | 로봇 제어 전체. 관제 PC 실행본과 동기화 |
| 화면·기록 | 저장소 `Final` 브랜치 | 데이터베이스 브릿지, 웹 API |

**`Final` 브랜치에도 제어 노드 파일이 존재하나 구버전 스냅샷이다.
운영 기준으로 삼지 않는다.**

**정본은 관제 PC 실행 트리다.** 저장소 사본과 차이가 있으면
실행 트리를 기준으로 한다.

### 1-2. 노드 구성

| 노드 | 실행 위치 | 패키지 | 역할 |
|---|---|---|---|
| `recycle_detection` | Docker | `object_detection` | YOLO 추론. 검출 결과 발행 |
| `tracking_pick_node` | 호스트 | `rocycle_robot` | 추적·예측·파지·판정·배치·상태 발행 |
| `v4l2_camera_node` | 호스트 | `v4l2_camera` | 고정 카메라 드라이버 |

| `conveyor_node` | 호스트 | `recycle_robot` | 컨베이어 시리얼 제어 |
| `tts_node` | 호스트 | `recycle_robot` | 음성 출력 |

### 1-3. 검출과 제어를 분리한 이유

**YOLO 추론이 수백 밀리초 걸린다. 같은 프로세스에서 실행하면
그동안 로봇 제어 콜백이 블로킹된다.**

**따라서 검출을 별도 컨테이너로 분리하고, 제어 노드는 그 결과를
토픽으로 구독한다.**

## 2. 처리 흐름

### 2-1. 단계별 흐름

```
① 검출
   고정 카메라 프레임에서 물체와 클래스를 식별
   신뢰도 0.6 미만은 결과에 포함하지 않음
   화면 가장자리 15px 이내에 걸친 검출은 폐기

② 좌표 변환
   화면 픽셀 → 벨트 평면 교차 → 로봇 좌표
   경험적 보정 적용

③ 추적
   프레임 간 동일 물체 매칭
   칼만 필터로 위치·속도 추정
   최대 3개 동시 추적

④ 확정
   연속 9프레임 동일 클래스 → 파지 대상 확정

⑤ 예측
   로봇 도달 시점의 물체 위치 계산
   품목별 보정값 적용

⑥ 준비
   그리퍼 개방 → 파지력 설정 → 힘 정규화 → 기준 무게 측정
   이 시간 전체가 예측에 포함됨

⑦ 파지
   예측 지점 상공 이동 → 수직 하강 → 그리퍼 닫기 → 대기

⑧ 계량
   고정 측정 자세로 이동 → 정지 → 무게 측정
   기준값과의 차이로 순 무게 산출

⑨ 판정
   품목별 라우팅 규칙 + 무게 조건

⑩ 배치
   통 상공 이동 → 수직 하강 → 개방 → 수직 상승
   개방 후 그리퍼 관절 위치로 배치 성공 확인
```

### 2-2. 상태 머신

```
IDLE ──시작──▶ RUNNING ──일시정지──▶ PAUSED
                  │                     │
                  │◀───────재개─────────┘
                  │
                 종료
                  ▼
              STOPPING ──보고──▶ IDLE
```

**일시정지와 종료는 현재 파지 사이클이 끝난 뒤 반영된다.**
물체를 든 채로 정지하지 않는다.

## 3. 주요 알고리즘

### 3-1. 좌표 변환

**고정 카메라에 깊이 정보가 없으므로 단일 이미지로는 3차원
위치를 구할 수 없다.**

**해결: 물체가 벨트 평면 위에 있다고 가정한다.**

```
1. 검출 박스의 하단 지점을 접점으로 본다
2. 카메라 내부 파라미터로 그 픽셀의 시선 벡터를 구한다
3. 시선 벡터와 벨트 평면의 교점을 계산한다
4. 경험적 보정을 적용한다
```

**카메라 내부 파라미터**

```
fx = 1427.5    fy = 1429.8
cx =  674.3    cy =  359.2
왜곡계수 [0.0838, -0.0067, -0.0059, 0.0080, 0]
```

**경험적 보정이 필요한 이유**: 이론 계산만으로는 실측 대비
계통 오차가 남았다. 벨트 위 여러 지점을 실측해 보정 함수를
구성했다.

**정확도**: RMS 4.5mm, 최대 8.6mm

### 3-2. 추적과 속도 추정

**칼만 필터 상태변수**

```
[위치, 속도]  등속도 모델
```

**속도 클램프**

```
4.6 ~ 5.3 mm/s
```

**클램프를 두는 이유**: 관측 구간이 짧아 속도 추정이 크게
흔들린다. 실측 분포가 -9.23 ~ 24.08mm/s까지 벌어졌으나 실제
벨트 속도는 약 4.98mm/s다. 클램프 폭을 좁게 두어 추정 잡음이
예측에 반영되지 않게 한다.

**부수 효과**: 속도가 사실상 상수로 고정되어 필터 구조를 바꾸지
않고 안정성을 얻는다.

### 3-3. 예측 파지 타이밍

```
예측 위치 = 현재 위치 + 속도 × (준비 + 이동 + 하강 시간)
```

**준비 시간에 반드시 포함해야 하는 것**

```
그리퍼 개방
파지력 설정 및 힘 정규화
기준 무게 측정
```

**이 동작들이 예측 계산 이후에 실행되면 그 시간만큼 물체가
더 이동하므로 파지가 빗나간다.**

**품목별 보정값**

| 품목 | 보정 |
|---|---|
| `can` | 0 |
| `battery` | +30mm |
| `plastic` | +20mm |

### 3-4. 검출 결과 누적 방지

**파지 동작이 콜백을 블로킹하는 동안 검출 결과가 큐에 쌓인다.**

**사이클 종료 시 한꺼번에 처리되면 확정 조건이 순식간에 충족되어
극히 짧은 구간의 속도로 장시간을 외삽하게 된다.**

**대책**: 도착 간격이 비정상적으로 짧으면 누적분으로 간주해
폐기한다.

**효과**: 확정 소요 시간이 0.008초에서 1.057초로 복원되었다.

### 3-5. 무게 판정

**측정 방식**

```
기준 무게    파지 전, 빈 그리퍼 상태
측정 무게    파지 후, 고정 측정 자세에서 정지 후
순 무게      측정 무게 − 기준 무게
```

**두 측정을 같은 자세에서 해야 하는 이유**: 로봇 자세가 다르면
중력 보정값이 달라져 약 200g의 계통 오차가 발생한다.

**측정 자세 도입 효과**: 순 무게 분산이 211.4g에서 46.8g으로
개선되었다. 실제 무게 대비 오차는 약 1.6g이다.

**임계값**

| 항목 | 값 |
|---|---|
| 판정 임계값 | 0.20kg |
| 계측 신뢰 하한 | -0.15kg |

**계측 신뢰 하한의 의미**: 순 무게가 음수로 크게 나오는 것은
물리적으로 불가능하므로 계측 실패로 간주하고 확인 필요 통으로
보낸다.

**하한값 산정 근거**: 로드셀 진동 진폭 ±45g의 포락선 바깥에
두어야 정상 측정을 오판하지 않는다.

**임계값을 통일한 이유**: 캔과 라벨 페트병 사이에 오분류가
발생하는데, 두 임계값을 같게 두면 어느 쪽으로 분류되든 결과가
같아진다.

### 3-6. 핸드오버 릴리즈 판정

**문제**: 사람이 당기는 것과 중력에 의한 처짐을 구분해야 한다.

**두 현상의 차이**

| | 속도 | 방향 |
|---|---|---|
| 사람의 당김 | 6~12mm/s | 수평 |
| 중력 처짐 | 최대 1.0mm/s | 하향 |

**판정 조건 (둘 다 만족해야 개방)**

```
조건 1   수평 속도 3.0mm/s 이상, 연속 2회
조건 2   하향 성분을 제외한 누적 변위 7mm 이상
```

**하향 성분을 제외하는 이유**: 처짐은 거의 전부 하향이므로,
하향을 빼면 처짐이 누적 변위 조건을 통과하지 못한다.

**설계 이력**: 초기에는 누적 3차원 변위만으로 판정했으나,
처짐이 15초간 19.4mm 누적되어 오탐 개방이 발생했다. 속도
조건 추가와 하향 성분 제외로 해결했다.

**미수령 처리**: 15초 경과 시 순응 제어를 해제하고 확인 필요
통으로 정상 배치한다. 제시 높이에서 개방하지 않는다.

### 3-7. 도달 한계 안전 정지

**정지 사유 집합**

```
파지 사이클 진행 중
도달 한계 접근
계량 중
```

**모든 사유가 해제되어야 컨베이어가 재가동된다.**

**비상 정지는 집합 밖에 둔다.** 사유 제거로 풀려서는 안 되기
때문이다.

| 항목 | 값 |
|---|---|
| 도달 한계 | x = 590mm |
| 정지 마진 | x = 540mm |
| 워치독 | 120초 |

**워치독 동작**: 120초가 지나도 사유가 해제되지 않으면 강제로
재가동하고 해당 물체를 무시 목록에 넣는다. 무시 목록의 물체는
파지 후보에서도 제외된다.

**워치독 시간 산정 근거**: 도달 한계 정지는 앞 물체의 잔여
사이클과 해당 물체 자신의 사이클에 걸쳐 유지된다. 정상 최대
2사이클(약 48초)에 재시도 여유를 더해 산정했다.

### 3-8. 배치 성공 확인

**그리퍼 개방 후 관절 위치로 물체가 실제로 놓였는지 확인한다.**

```
배치 성공   -0.4793 ~ -0.2856 rad
파지 실패   +0.1622 rad
경계값      -0.06 rad
```

**두 군집 간격이 0.448rad로 명확히 갈린다.**
**과거 11건 재판정 결과 11/11 정답.**

### 3-9. 미지 클래스 방어 (설계 완료, 미구현)

**모델을 교체했을 때 설정에 없는 클래스가 들어오면 파지 도중
예외가 발생한다.**

**3중 방어 설계**

```
0차   기동 시 모델 클래스 목록과 설정 파일을 대조
1차   검출 수용 단계에서 미지 클래스는 추적 대상으로 만들지 않음
2차   라우팅 조회 실패 시 확인 필요 통으로 폴백
```

## 4. 분류 체계

### 4-1. 인식 클래스

| 클래스 | 대상 |
|---|---|
| `can` | 캔 |
| `battery` | 건전지 (AA) |
| `paper` | 종이 상자 |
| `pet_labeled` | 라벨 붙은 페트병 |
| `plastic` | 페트병이 아닌 플라스틱 (뚜껑, 용기류) |
| `plastic_bag` | 비닐 (묶인 것) |

### 4-2. 라우팅 규칙

| 클래스 | 목적지 | 조건 |
|---|---|---|
| `can` | `can_bin` | 순 무게 0.20kg 미만 |
| `can` | `review_bin` | 순 무게 0.20kg 이상 |
| `battery` | `battery_bin` | — |
| `plastic` | `plastic_bin` | 무게 측정 없음 |
| `plastic_bag` | `review_bin` | 재질 판별 불가 |
| `pet_labeled` | 사람 전달 | 순 무게 0.20kg 미만 |
| `pet_labeled` | `review_bin` | 순 무게 0.20kg 이상 |
| 미검출 | 벨트 끝 | 로봇이 손대지 않음 |

**`paper`는 라우팅 규칙이 없다 — 운영 대상에서 제외됨(위
4-1의 인식 클래스에는 있지만 실제로 배정되는 목적지가 없다는
뜻).** 화면상 좌우 위치에 따라 `pet_labeled`와 100%(양쪽 신뢰도
0.92~0.95) 갈리는 결정경계 문제가 있어(C-03, 4번의 재검증 끝에
확정) `paper_bin` 자체를 운영하지 않는다. `paper`로 검출되는
물체는 현재 어느 통으로도 정상 배정되지 않으니 시연·운영에
투입하지 말 것.

**`review_bin`이 여러 사유를 받는 이유**: 재질별 4개 통과
달리 처리 상태별 통이다. 판정이 불확실하거나 사람 확인이
필요한 모든 경우를 모은다.

## 5. 설정 파라미터

### 5-1. 품목별 파지 조건

| 품목 | 파지력 | 대기 | 하강 깊이 | 예측 보정 | 배치 확인 |
|---|---|---|---|---|---|

## 7. 데이터베이스 연동

### 7-1. 구조

```
제어 노드 ──/ui/state──▶ 브릿지 ──HTTP──▶ 웹 API ──▶ 데이터베이스
```

### 7-2. 테이블

| 테이블 | 내용 |
|---|---|
| `waste_type` | 클래스별 처리 규칙 마스터 |
| `processing_log` | 처리 이력 (1건당 1행) |
| `robot_event` | 처리 건에 딸린 이벤트 로그 |

**`processing_log` 주요 필드**

```
external_id, waste_type_id, confidence, action, destination,
result, status, review_reason, weight, created_at,
final_waste_type_id, final_destination, completed_at,
reviewed_at, reviewed_by
```

**라인 또는 로봇 식별자 필드는 없다.** 다중 로봇 확장 시 추가가
필요하다.

### 7-3. 설계 원칙

**브릿지는 상태 토픽을 구독만 하며, 로봇이나 컨베이어를 제어하는
경로를 갖지 않는다.**

**따라서 데이터베이스가 정지해도 로봇 동작에 영향이 없다.**

**단, 이는 코드 구조로 확인한 것이며 실제 장애 상황을 재현한
검증은 수행하지 않았다.**

### 7-4. 전송 조건

```
배치 완료 시점에만 전송 (진행 중인 사이클은 무시)
중복 전송 방지 식별자 사용
전송 실패 시 큐에 보관 후 재시도
큐 초과 시 오래된 항목부터 폐기
```
