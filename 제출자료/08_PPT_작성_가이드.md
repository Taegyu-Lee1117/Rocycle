# PPT 작성 가이드

**용도** 발표 + 포트폴리오 겸용 슬라이드 제작
**전제** 분량 제한 없음 (80~100장 가능), 발표 시 건너뛰며 진행
**작성일** 2026-09-10
**문서 버전** 2.0

---

## 1. 이 문서의 전제

**PPT가 두 역할을 동시에 한다.**

```
발표      15~20장만 보여주며 건너뛰며 진행
포트폴리오 나중에 혼자 읽는 사람이 이해할 수 있어야 함
```

**두 요구가 상충한다.**

| | 발표용 | 포트폴리오용 |
|---|---|---|
| 글자 | 최소 | 충분히 |
| 설명 | 말로 | 슬라이드에 |
| 한 장의 정보량 | 하나 | 여러 개 |

**한 파일에 두 종류의 슬라이드를 섞되, 역할을 명확히 나눈다.**

---

## 2. 구조 — 발표용과 상세용의 이원 구조

### 2-1. 기본 패턴

**발표용 장 하나 뒤에 그 주제의 상세 장들을 붙인다.**

```
15장   발표용   "4.5mm"
16장   상세     좌표 변환 방식
17장   상세     캘리브레이션 실패 3회
18장   상세     보정 함수와 실측 데이터

19장   발표용   "0.51 ~ 0.91"
20장   상세     신뢰도 분포 전체
21장   상세     무게 게이트 설계
```

**발표에서는 15장 → 19장으로 건너뛴다.**

**질문이 나오면 16~18장으로 되돌아간다.**

**포트폴리오로 읽을 때는 순서대로 읽으면 된다.**

### 2-2. 발표 동선을 미리 정한다

**슬라이드 하단에 다음 발표 장 번호를 작게 표시하면 좋다.**

```
[15] ──▶ [19] ──▶ [24] ──▶ [31] ...
```

**발표자가 헤매지 않는다.**

**또는 발표용 장에만 색을 다르게 하거나 표시를 두는 방법도 있다.**

### 2-3. 발표용 장의 비율

```
전체 90장 기준
발표용 15~20장
상세용 70~75장
```

**발표용이 20장을 넘으면 건너뛰는 의미가 없어진다.**

## 3. 발표용 슬라이드 — 잡스식

### 3-1. 원칙

```
한 장에 메시지 하나
글자는 열 단어 이내
숫자 하나 또는 그림 하나
나머지는 말로 한다
```

**슬라이드를 읽지 않는다. 슬라이드는 말을 뒷받침한다.**

### 3-2. 숫자 하나로 되는 것들

**본 프로젝트에는 숫자만으로 메시지가 서는 것이 여럿 있다.**

| 숫자 | 전달되는 것 |
|---|---|
| `4.5mm` | 좌표 정확도. 그리퍼 110mm 대비 여유 |
| `1.6g` | 무게 측정 오차 |
| `77 / 77` 과 `0 / 77` | 자세에 따른 검출 성패 |
| `7 / 7` | 완주 시험 전 품목 성공 |
| `±45g` | 힘 센서 진동. 정밀 계량이 안 되는 이유 |
| `27초` | 진동 주기. 평균으로 못 지우는 이유 |
| `4` | 종이 오분류 원인이 뒤집힌 횟수 |
| `698% → 30%` | GPU 전환 시 검출 노드 CPU 점유 변화 |
| `-97.6g` | 빈 캔이 이 값으로 측정돼도 캔 통으로 갔다 |

**슬라이드에 숫자만 크게 띄우고 설명은 말로 한다.**

### 3-3. 두 줄 대비로 되는 것

**가장 강력한 슬라이드 후보다.**

```
정답 분류    0.63 ~ 0.92
오분류      0.51 ~ 0.91
```

**두 줄을 나란히 보여주면 "겹친다"가 한눈에 보인다.**

**말**: "신뢰도로는 정답과 오분류를 구분할 수 없습니다.
그래서 사람에게 건네는 판단을 비전이 아닌 무게로 바꿨습니다."

**다른 대비 후보**

```
당김    6 ~ 12 mm/s
처짐    1 mm/s 이하

빈 캔        +44.2g
내용물 캔    +494.2g

자세 통일 전   211.4g
자세 통일 후    46.8g

CPU 모드   검출 노드가 7코어
GPU 모드   0.3코어
```

**빈 캔 세 번의 측정값도 좋은 대비다.**

```
1회차   -97.6g
2회차   -22.1g
3회차   +44.3g
        → 전부 캔 통
```

**142g 폭으로 흔들려도 판정이 일관됐다.** 임계값 200g 대비
여유가 충분하다는 것이 한눈에 보인다.

### 3-4. 그림 하나로 되는 것

```
시스템 아키텍처 도면
파지 순간 사진
확인 필요 통에 모인 물체 사진
안전 설계 계층도
```

**아키텍처 도면은 발표용과 상세용 두 벌을 만드는 것이 좋다.**

```
발표용   박스 5개 정도로 단순화
상세용   토픽·서비스까지 전부
```

### 3-5. 문장 하나로 되는 것

**발표의 주제문은 슬라이드에 그대로 띄운다.**

```
"판단할 수 없으면 판단하지 않는다"

"분류 결과를 안전 게이트로 쓰지 않는다"

"완전 자동화가 아니라,
 어디부터 사람이 필요한가를 구분한 시스템"
```

**이런 장은 글자만 있고 다른 것이 없어야 한다.**

## 4. 발표 구성안

**발표 15~20장 기준. 각 장 뒤에 상세 장이 붙는다.**

### 4-1. 전체 흐름

| 순서 | 발표용 장 | 메시지 | 시간 |
|---|---|---|---|
| 1 | 제목 | — | 30초 |
| 2 | 문제 제기 | 재활용 분류는 겉모습만으로 안 된다 | 1분 |
| 3 | 주제문 | 판단할 수 없으면 판단하지 않는다 | 30초 |
| 4 | 시연 영상 | — | 3분 |
| 5 | 아키텍처 (단순화) | 시스템 구성 | 1분 30초 |
| 6 | `4.5mm` | 깊이 없이 좌표를 구했다 | 1분 30초 |
| 7 | 예측 파지 그림 | 멈추지 않고 집는다 | 1분 30초 |
| 8 | `+44g / +494g` | 무게로 내용물을 판별한다 | 1분 30초 |
| 9 | `±45g / 27초` | 정밀 계량은 원리적으로 불가 | 1분 |
| 10 | 당김 대 처짐 | 사람에게 넘기는 판단 | 1분 30초 |
| 11 | `0.63~0.92 / 0.51~0.91` | 비전을 안전 게이트로 못 쓴다 | 2분 |
| 12 | 안전 계층도 | 층층이 쌓인 안전장치 | 1분 30초 |
| 13 | `4` | 원인 규명이 네 번 뒤집혔다 | 2분 |
| 14 | `7 / 7` × 3 | 완주 결과 (3회) | 1분 |
| 15 | 한계 목록 | 확인하고 뺀 것들 | 1분 30초 |
| 16 | 마무리 문장 | — | 30초 |

**합계 약 22분 + 질의응답 8분.**

### 4-2. 영상 위치

**4번(앞)을 권한다.**

```
앞에 두면   무엇을 만들었는지 먼저 보여주고 설명으로 들어간다
            청중이 그림을 갖고 듣는다
뒤에 두면   설명을 듣고 확인하는 흐름
```

**본 프로젝트는 시연 장면이 설명을 크게 줄여준다.**

### 4-3. 11번과 13번이 핵심이다

**11번**: 이 프로젝트에서 가장 설명할 가치가 있는 설계 판단이다.

```
비전이 틀릴 수 있다는 것을 데이터로 보여주고
그래서 안전 판단을 물리량으로 옮겼다는 흐름
```

**13번**: 검증 방법론을 보여준다.

```
결론만 보여주면 쉬워 보인다
네 번 뒤집힌 과정이 오히려 강점이다
```

**두 장에 시간을 가장 많이 배정한다.**

## 5. 상세 슬라이드 — 포트폴리오용

### 5-1. 산출물 문서를 그대로 옮긴다

**이미 작성된 산출물이 상세 슬라이드의 원본이 된다.**

| 산출물 | 슬라이드로 옮길 부분 |
|---|---|
| 기능 명세서 | 시스템 구성, 처리 흐름, 알고리즘, 파라미터 표 |
| 결과물 및 보고서 | 실측값 표, 시행착오 사례 전체 |
| 요구사항 명세서 | 요구사항 표, 제약사항 |
| 다중 로봇 확장 설계 | 확장 준비도 표 |
| 보안 정책 | 안전 설계, 위협 모델 |

**표는 그대로 옮겨도 된다.** 포트폴리오는 읽는 문서다.

### 5-2. 상세 슬라이드에는 글자가 많아도 된다

**발표에서 안 보여주는 장이므로 잡스식 원칙을 적용하지 않는다.**

**다만 한 장에 한 주제는 지킨다.**

### 5-3. 상세 장의 구성 제안

```
시스템 구성      10~12장
  하드웨어, 노드, 토픽, 처리 흐름

알고리즘         15~20장
  좌표 변환, 추적, 예측, 무게, 핸드오버, 안전 정지

시행착오         15~20장
  사례별로 2~3장씩 (증상 → 가설 → 검증 → 결론)

실측 데이터      10~12장
  정확도, 성능, 각 판정의 근거 수치

설계 원칙        5장
  원칙별로 어떤 실패에서 나왔는지

한계와 과제      5~8장

확장 설계        5장

부록             나머지
  설정값 전체, 명령어, 체크리스트
```

**합계 70~85장.**

## 6. 시행착오 슬라이드 — 상세하게

**포트폴리오의 차별점이 여기서 나온다.**

### 6-1. 사례별 구성

**한 사례를 2~3장으로 나눈다.**

```
1장   증상
      "같은 종이 상자가 때로는 종이, 때로는 페트병"

2장   가설과 기각
      1차 조명 → 대책 없음
      2차 카메라 간섭 → A/B로 기각
      3차 배치 자세 → 승인까지 했다가 철회
      4차 화면 위치 → 확정

3장   결론과 조치
      결정 경계 위의 물체. 회피 불가
      운영 대상에서 제외
```

### 6-2. 넣을 사례

```
좌표 변환 3회 실패
핸드오버 오탐 개방
무게 측정 분산
종이 오분류 4회 재정정      ★가장 상세하게
컨베이어 속도 측정 오류
검출 결과 누적
판정 지표 폐기
문서와 실물의 불일치
```

### 6-3. 실패를 숨기지 않는 이유

**포트폴리오를 읽는 사람은 결과보다 과정을 본다.**

```
"됐다"만 있으면 운인지 실력인지 모른다
"이렇게 틀렸고 이렇게 찾았다"가 실력을 보여준다
```

## 7. 쓰면 안 되는 값

**아래는 사실과 다르거나 폐기된 값이다.**

| 표현 | 이유 | 대신 |
|---|---|---|
| 컨베이어 2.0cm/s | 문서값 오류 | 벨트 표면 약 5.0mm/s |
| CPU로 추론한다 | GPU 전환 완료 | 현재 GPU 추론 |
| 벨트 무정지로 동작한다 | 파지 중 정지 유지 | 파지 사이클 동안 컨베이어 정지 |
| 배치 확인 4/4 | 표본 확대로 폐기 | 11건 기준 11/11 |
| `pet_unlabeled` | 삭제된 클래스 | 현재 6종만 |
| 플라스틱 파지력 10N | 중간 단계 값 | 15N |
| 2대 PC 구성 | 1대로 운영 | 아래 7-1절 |
| 정밀하게 무게를 측정 | 진동으로 불가 | 내용물 유무를 판별 |
| 안전이 확정됐다 | 검증 회수 기준 미달 | 오탐 0건 확인 |

### 7-1. PC 구성 서술

> 현재는 한 대에서 운영합니다. 초기 설계는 관제 PC와 로봇 PC
> 2대 분산이었고, 나누면 장애가 격리되고 여러 라인으로 확장할
> 수 있습니다. 다만 저희 구성에서는 카메라 간 대역폭 경합이
> 실측으로 확인되지 않아 분리의 실익이 없었습니다.

### 7-2. GPU 서술

**GPU로 추론한다. 다만 처리량이 올라간 것은 아니다.**

> GPU로 추론합니다. 다만 발행률은 거의 그대로입니다. 카메라
> 프레임이 7.5Hz로 상한이라 추론이 빨라져도 더 낼 것이 없기
> 때문입니다. **얻은 것은 처리량이 아니라 연산 자원입니다.**
> 검출 노드가 쓰던 7코어가 0.3코어로 줄었습니다.

**전환 전 우려했던 문제가 발생하지 않은 이유도 함께 설명할 수
있다.**

> 전환하면 확정까지 걸리는 시간이 짧아져 속도 추정이 나빠질
> 것으로 예상했는데, **발행률이 카메라에 묶여 있어 그 우려가
> 성립하지 않았습니다.** 파라미터 조정 없이 그대로 동작했습니다.

### 7-3. 벨트 동작 서술

**파지 사이클 동안 컨베이어가 정지한다.**

> 물체를 집는 동안 컨베이어를 정지시킵니다. 무정지 방식도
> 시험했으나, **벨트 진동이 무게 측정에 실려 빈 캔이 106g으로
> 잘못 측정**되는 문제가 나와 적용하지 않았습니다.

**도달 한계 안전 정지는 별개로 구현·검증되어 유효하다.**

> 가장 앞선 미처리 물체가 로봇 도달 범위에 가까워지면 컨베이어를
> 정지시킵니다. 이 기능은 인터록과 별개로 동작합니다.

### 7-4. 조건을 붙여야 하는 표현

| 표현 | 붙일 조건 |
|---|---|
| 신뢰도 최솟값 | "파지 트리거 구간에서" |
| 비스듬하면 검출 안 됨 | "캔에서 확인. 다른 품목 미확인" |
| 데이터베이스가 죽어도 로봇이 안 멈춘다 | "코드 구조상. 실제 장애 재현은 미검증" |
| 회전각 추정 | "추정기만 구현. 적용은 하지 않음" |

## 8. 시연 영상 자막

**영상이 3분이고 설명 없이 흘러가므로 자막이 필요하다.**

```
빈 캔 → 캔 통
건전지 → 건전지 통
플라스틱 뚜껑 → 플라스틱 통
장갑 — 학습하지 않은 물체는 손대지 않습니다
비닐 — 재질을 판단할 수 없어 확인 필요 통으로
내용물 든 캔 — 무게를 재서 내용물을 확인합니다
라벨 페트병 — 사람이 라벨을 제거해야 합니다
종료 및 결과 보고
```

**시간은 실제 영상에 맞춰 조정한다.**

---

## 9. 제작 시 확인할 것

```
□ 발표용 장이 15~20장인가
□ 발표용 장에 글자가 열 단어 이내인가
□ 발표 동선이 표시되어 있는가
□ 7절 금지 표현이 들어가지 않았는가
□ 실측값에 조건이 붙었는가 (7-4절)
□ 아키텍처 도면이 발표용·상세용 두 벌인가
□ 시행착오가 사례별로 나뉘어 있는가
□ 한계 슬라이드에 회피 방안이 함께 있는가
□ 영상 위치가 정해졌는가
```

## 10. 완성 후 요청할 것

**PPT가 확정되면 아래를 작성한다.**

```
발표 스크립트    발표용 장별 발화 내용, 시간 배분, 건너뛰기 지점
발표자용 학습자료  내용 이해 + 예상 질문과 답변
```

**필요한 정보**

```
전체 장수
발표용으로 쓸 장 번호 목록
각 발표용 장의 제목과 담긴 내용
영상의 최종 길이와 배치 위치
발표자가 몇 명이고 어디서 나뉘는지
```

**발표용 장 번호 목록이 가장 중요하다.** 스크립트가 그 순서로
작성된다.
