# 보안 정책 및 가이드라인

**프로젝트명** 컨베이어 기반 재활용 분류 협동로봇
**작성일** 2026-09-10
**문서 버전** 2.0

---

## 1. 문서 개요

### 1-1. 목적

본 문서는 로봇 시스템 운용에 관련된 보안 요소를 정의한다.
네트워크, 접근 제어, 데이터, 물리 안전을 다룬다.

### 1-2. 적용 범위

교육·연구 목적의 단일 로봇 시스템이며, 상용 운영 환경을
전제하지 않는다. **현재 구현 수준을 있는 그대로 기술하고,
상용화 시 필요한 보완 사항을 별도로 정리한다.**

### 1-3. 위협 모델

**본 시스템에서 실제로 고려해야 하는 위협은 아래와 같다.**

```
물리적 위험    로봇 동작 범위 내 사람의 접근
오작동         잘못된 명령이나 설정으로 인한 예기치 않은 동작
데이터 손실     코드·설정·캘리브레이션 결과의 유실
무단 조작       인가되지 않은 사용자의 로봇 제어
```

**외부 네트워크로부터의 공격은 현재 구성에서 주된 위협이
아니다.** 시스템이 폐쇄망에 있고 외부 노출이 없기 때문이다.

## 2. 네트워크

### 2-1. 구성

| 구간 | 용도 | 주소 |
|---|---|---|
| 로봇망 | 로봇 컨트롤러, 그리퍼 | 192.168.1.32 |
| 사내망 | 화면, 데이터베이스 연동 | 172.24.3.240 |

**연결 대상**

```
로봇 컨트롤러   192.168.1.100
그리퍼          192.168.1.1 (Modbus TCP 502)
화면·기록 서버   172.24.0.31
```

**로봇 제어 트래픽과 일반 트래픽이 분리되어 있다.**

### 2-2. 현재 상태

| 항목 | 상태 |
|---|---|
| 로봇 컨트롤러 접근 제어 | 없음 (동일 대역에서 접근 가능) |
| ROS2 통신 암호화 | 없음 (기본 설정) |
| 화면 접근 인증 | 없음 |
| 외부 노출 | 없음 (폐쇄망) |
| 제어 PC 외부 LISTEN 포트 | 없음 (실측 확인) |

**제어 PC에서 외부로 열린 포트가 없다.** 화면과 데이터베이스는
별도 PC에서 동작한다.

### 2-3. 위험

**같은 대역에 접속할 수 있으면 로봇을 제어할 수 있다.**

```
로봇 서비스를 직접 호출해 로봇을 움직일 수 있다
컨베이어 제어 토픽에 발행할 수 있다
화면 조작 버튼과 동일한 명령을 보낼 수 있다
```

### 2-4. 현재 대응

```
폐쇄망 운용
물리적 접근이 통제된 실습실 환경
로봇 동작 중 사람이 항상 입회
```

### 2-5. 상용화 시 필요한 보완

```
ROS2 DDS 보안 기능 적용
로봇망 접근 제어 (방화벽, 망 분리)
화면 접근 인증 도입
명령 발행 주체 인증
```

## 3. 접근 제어

### 3-1. 현재 상태

| 항목 | 방식 |
|---|---|
| 제어 PC 로그인 | 운영체제 계정 |
| 저장소 접근 | SSH 키 |
| 데이터베이스 접근 | 환경 변수로 주입 |
| 로봇 티치 펜던트 | 물리적 접근 |

### 3-2. 자격 증명 관리 — 확인 결과

**데이터베이스 접속 정보를 조사한 결과는 아래와 같다.**

| 항목 | 확인 내용 |
|---|---|
| 관리 방식 | 환경 변수 |
| 설정 항목 | 호스트, 포트, 데이터베이스명, 사용자, 비밀번호, API 호스트·포트 |
| 실제 설정 파일 | 제어 PC에 존재하지 않음 (예시 파일만 있음) |
| 코드 기본값 | 비밀번호가 빈 문자열 |
| 버전 관리 제외 | 설정 파일이 제외 목록에 포함됨 |
| 유출 흔적 | 실제 비밀번호가 저장소에 들어간 흔적 없음 |

**결론: 현재 구성에서 노출된 평문 비밀번호는 없다.**

**개선 과제**: 코드 기본값이 빈 문자열이다. 실제 운영 배포 시
반드시 강한 값으로 교체해야 한다.

### 3-3. 권한 분리

**현재는 단일 사용자 환경으로 권한 구분이 없다.**

**상용화 시 필요한 구분**

| 역할 | 권한 |
|---|---|
| 운영자 | 시작·정지, 상태 조회 |
| 관리자 | 설정 변경, 캘리브레이션 |
| 개발자 | 코드 배포 |

## 4. 데이터 보호

### 4-1. 저장 데이터

**데이터베이스 구조**

| 테이블 | 내용 |
|---|---|
| `waste_type` | 클래스별 처리 규칙 |
| `processing_log` | 처리 이력 |
| `robot_event` | 처리 건에 딸린 이벤트 |

**처리 이력에 저장되는 항목**

```
식별자, 예측 클래스, 신뢰도, 동작, 목적지, 결과,
상태, 검토 사유, 순 무게, 시각, 검토자
```

### 4-2. 개인정보

**스키마 전수 확인 결과 이름·연락처·이메일·사번 등의 항목은
없다.**

**단 하나 확인이 필요한 항목**

```
검토자 필드 (reviewed_by)
```

**이 필드에 실제로 무엇이 들어가는지 미확인이다.** 운영자
식별자인지 고정 문자열인지에 따라 개인정보 해당 여부가 달라진다.

**운영 전 확인이 필요하다.** 실명이 들어간다면 개인정보 처리
방침이 필요하다.

### 4-3. 영상 처리

```
고정 카메라   벨트 위 물체만 촬영
손목 카메라   그리퍼 주변만 촬영
저장          영상·이미지를 저장하지 않음
```

**데이터베이스 연동 코드 전수 확인 결과 이미지 저장 관련 항목이
없다.**

**사람이 화면에 잡힐 수 있는 구간**: 핸드오버 시 사람의 손이
손목 카메라에 들어올 수 있다. **저장하지 않으므로 보관 이슈는
없다.**

**상용화 시**: 작업자가 촬영되는 구성이라면 촬영 고지와 보관
정책이 필요하다.

### 4-4. 데이터 손실 방지

**본 프로젝트에서 실제로 발생했던 위험**

```
실행 중인 코드 일부가 저장소에 반영되지 않은 상태로
디스크 한 곳에만 존재했다
```

**조치**: 별도 백업 생성 후 저장소에 반영했다.

**대책**

```
작업 종료 시 변경분을 반드시 버전 관리에 반영
정기 백업
백업본에 실행 중인 버전이 포함되었는지 확인
```

### 4-5. 모델 파일 관리

**모델 파일이 여러 버전 존재할 수 있다.**

**본 프로젝트에서 패키지에 포함된 파일이 구버전이고, 실제 운용
모델은 별도 경로에서 읽히는 상태였다.**

**백업 시 실제 운용 버전을 확인한다.** 구버전을 정본으로
착각하면 복구 후 동작이 달라진다.

## 5. 물리 안전

**로봇 시스템에서 가장 직접적인 위험 요소다.**

### 5-1. 안전 장치

| 장치 | 동작 |
|---|---|
| 물리 비상정지 버튼 | 로봇 전원 차단 |
| 화면 비상정지 | 컨베이어 즉시 정지, 로봇 정지 명령 전달 |
| 관절 가동 범위 제한 | 물리 한계보다 좁게 설정 |
| TCP 힘 한계 | 160N 초과 시 안전 정지 |
| 도달 한계 정지 | 물체가 범위를 벗어나기 전 컨베이어 정지 |

### 5-2. [중요] 화면 비상정지의 한계

```
컨베이어    즉시 정지 확인됨
로봇        정지 명령 전달은 확인. 즉시 정지는 미검증
```

**위급 상황에서는 물리 비상정지 버튼을 사용한다.**

**화면에도 이 안내를 상시 표시한다.**

### 5-3. 사람과의 상호작용

**핸드오버 시 사람이 로봇 작업 영역에 접근한다.**

**안전 조치**

```
순응 제어로 강성을 낮춰 접촉 시 유연하게 반응
전달 전 무게를 확인해 위험한 물체를 걸러냄
사람이 받지 않으면 15초 후 스스로 회수
```

**운영 규칙**

```
로봇 동작 중 작업 영역 안으로 들어가지 않는다
핸드오버 시에만 지정된 위치에서 물체를 받는다
비상정지 버튼에 항상 손이 닿는 위치에 사람이 있는다
```

### 5-4. 비상 정지 후 복구

**비상 정지 후 자동으로 재개하지 않는다.**

**이유**: 정지 시점에 로봇이 물체를 들고 있었는지, 사람이 작업
영역에 있는지를 소프트웨어가 확신할 수 없다.

**복구 절차**

```
1. 작업 영역에 사람이 없는지 확인
2. 로봇이 물체를 들고 있으면 수동 회수
3. 노드 재시작
4. 시작 자세 확인 사이클 수행
5. 수동으로 작업 재개
```

### 5-5. 시뮬레이션 모드 확인

**제어 노드 설정 기본값이 시뮬레이션 모드다.**

**실동작 시 명시적으로 꺼야 한다.**

**반대로, 안전 확인이 필요한 상황에서는 시뮬레이션 모드로
먼저 실행해 로봇을 움직이지 않고 로직을 검증할 수 있다.**

## 6. 운영 보안 수칙

### 6-1. 일상 운용

```
□ 작업 시작 전 비상정지 버튼 위치 확인
□ 로봇 동작 중 작업 영역 접근 금지
□ 설정 변경 시 변경 내용과 사유 기록
□ 작업 종료 시 변경분 버전 관리 반영
□ 실행 인자에 시뮬레이션 여부 확인
```

### 6-2. 설정 변경

```
변경 전   현재 값을 기록한다
변경 후   변경 사유를 함께 남긴다
빌드      설정은 빌드 후에 반영된다
검증      변경이 영향을 주는 항목을 재검증한다
```

**검증되지 않은 값으로 로봇을 동작시키지 않는다.**

### 6-3. 코드 배포

```
실행 중인 코드와 저장소 내용이 일치하는지 확인
배포 후 기동 확인 절차 수행
문제 발생 시 되돌릴 수 있는 상태를 유지
```

## 7. 현재 수준 요약

**본 시스템은 교육·연구 목적의 폐쇄망 환경을 전제한다.**

| 영역 | 현재 수준 | 상용화 시 필요 |
|---|---|---|
| 네트워크 | 폐쇄망, 접근 제어 없음 | 통신 보안, 망 분리 |
| 인증 | 운영체제 계정 수준 | 역할 기반 접근 제어 |
| 자격 증명 | 환경 변수, 유출 없음 | 기본값 강화 |
| 데이터 | 개인정보 없음 (한 항목 확인 필요) | 영상 처리 정책 |
| 물리 안전 | 다층 안전장치 구현 | 안전 인증 |

**"보안이 충분하다"고 주장하지 않는다.**
**현재 환경에서 필요한 수준을 갖췄고, 상용화 시 무엇이 더
필요한지를 구분해 기술했다.**

## 8. 개선 과제

| 우선순위 | 항목 |
|---|---|
| 높음 | 로봇 정지 명령의 즉시성 검증 |
| 높음 | 실행 코드와 저장소 일치 보장 |
| 높음 | 검토자 필드의 실제 저장 값 확인 |
| 중간 | 데이터베이스 기본 비밀번호 강화 |
| 중간 | 화면 접근 인증 |
| 낮음 | 통신 보안 적용 |
| 낮음 | 역할 기반 권한 분리 |

**상위 두 항목은 보안보다 안전·신뢰성에 가깝지만, 시스템 무결성
관점에서 함께 관리한다.**
