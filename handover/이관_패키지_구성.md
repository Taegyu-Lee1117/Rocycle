## 2. 실행 파일(노드) — `setup.py`의 `entry_points`

```
tracking_node       = rocycle_robot.tracking_node:main
voice_bridge_node   = rocycle_robot.voice.voice_bridge_node:main
conveyor_node       = rocycle_robot.conveyor_node:main
```

**[전제, 중요] launch 파일은 없습니다.** 세 노드를 각각 따로
띄워야 합니다(아래 6절 실행 순서 참고). 하나로 묶는 launch 파일을
만드는 건 이관 후 여유가 되면 하면 좋은 개선사항이지, 지금 당장
필수는 아닙니다.

## 3. [중요] 이 패키지는 아직 `colcon build`로 설치된 적이 없습니다

**[원문]** 8일 내내 이 패키지를 `colcon build` + `ros2 run`으로
실행한 적이 없습니다 — 매번 파이썬 스크립트 맨 위에서
`sys.path.insert(0, ".../rocycle_robot")`으로 소스 디렉터리를
직접 경로에 넣고, `rclpy.init()` 후 노드 클래스를 직접
인스턴스화하는 방식으로 실행·테스트했습니다.

**이유**: `config_loader.py`/`routing.py` 등이 모델·설정 파일
경로를 `Path(__file__).resolve().parents[N]`으로 계산하는데, 이게
**소스 트리 기준**입니다 — 정식 `colcon build` 설치본(보통
`install/rocycle_robot/lib/python3.x/site-packages/...`로 복사됨)
으로는 `config/`, `models/`가 함께 안 따라가서 그대로는 안 될
가능성이 높습니다(`setup.py`의 `data_files`에 이 디렉터리들이
등록돼 있지 않음 — 확인 완료).

**권장 실행 방법(지금까지 검증된 방식)**:
```bash
export PYTHONPATH="$PYTHONPATH:/경로/rocycle_robot"
python3 -m rocycle_robot.tracking_node
# 또는
python3 -c "
import rclpy
from rocycle_robot.tracking_node import TrackingNode
rclpy.init()
node = TrackingNode()
rclpy.spin(node)
"
```

**정식으로 `ros2 run rocycle_robot tracking_node`가 되게 만들려면**
`setup.py`의 `data_files`에 `config/`, `models/`를 추가하고
`colcon build`로 설치해야 합니다 — 이건 저희도 안 해본 작업이라
이관 후 함께 확인이 필요합니다(6절 체크리스트의 "빌드" 항목 참고).

## 4. 실제 필요한 의존성 (import 전수 조사 결과)

**[원문] apt(ROS2 공식 패키지)**:
```
ros-jazzy-cv-bridge     (설치 확인됨, 4.1.0)
ros-jazzy-usb-cam       (설치 확인됨, 0.8.1 — C270 구동에 사용)
python3-opencv          (4.6.0 — 아래 pip 경고 참고)
```

**[원문] pip**:
```
ultralytics==8.4.140    (YOLO 추론)
numpy<2                 (실사용 1.26.4)
pyyaml
```

**[중요, 알려진 함정] `pip install opencv-python`을 절대 별도로
설치하지 마세요.** `ultralytics`가 최신 `opencv-python`을 끌어오면서
`numpy`를 2.x로 올리는데, 이게 `cv_bridge`(numpy 1.x 기준 컴파일됨)
를 깨뜨립니다. `opencv-python` pip 패키지가 이미 있다면 제거하고
시스템 `python3-opencv`만 쓰세요. GPU에서 CUDA torch를 새로 설치할
때도 numpy 버전이 다시 밀려 올라가지 않는지 설치 후 반드시
확인하세요(`python3 -c "import numpy; print(numpy.__version__)"`
가 2.x 미만이어야 함).

**[원문, 선택] pip — `IntentClassifier` 폴백 경로에만 필요, 지금
안 씀**:
```
python-dotenv
langchain-core
langchain-openai
```
(5절 참고 — 이 세 개는 설치 안 해도 `tracking_node`/
`voice_bridge_node`의 실제 사용 경로는 정상 동작합니다. 단
`intent_classification.py`를 직접 `import`하려는 코드가 있으면
`ImportError`가 납니다 — 지금은 아무도 그걸 안 부릅니다.)

**[원문, 커스텀] 로봇 관련 메시지 패키지** — `tracking_node.py`가
`dsr_msgs2`/`onrobot_rg_msgs`를 (dry_run=False일 때만) import
합니다:
```
dsr_msgs2         -- ~/ws_cobot_pjt/ws_dsr/src/doosan-robot2
onrobot_rg_msgs   -- ~/ws_cobot_pjt/ws_dsr/src/onrobot-ros2
```
**[확인 필요]** 이 두 저장소를 전체 빌드해야 하는지, 메시지
정의(`*.msg`/`*.srv`)만 빌드 가능한지는 저희도 확실하지 않습니다
— 지금까지는 로봇 PC에 이미 이 워크스페이스(`ws_dsr`)가 전체
빌드돼 있는 상태에서만 실행해봤습니다. 관제 PC에서 `tracking_node`
를 그대로 돌리려면(2-2절 "통째로 옮기기" 방향) 이 메시지 정의가
필요합니다 — 물리 로봇 드라이버 전체(`doosan-robot2`의 하드웨어
연결 부분)까지는 필요 없을 것 같지만[추론], 실제로 분리 빌드가
되는지는 관제 PC에서 시도해보고 안 되면 로봇 PC 담당에게
`ws_dsr` 저장소를 그대로 공유받는 방향으로 가는 게 안전합니다.

## 5. `IntentClassifier`(OpenAI 기반) — 왜 포함됐고 왜 안 쓰는지

`rocycle_robot/voice/intent_classification.py`는 원래 STT 원문
텍스트를 직접 분류하려고 만든 모듈인데, **팀원 쪽이 이미 자체
분류까지 끝낸 값(`/voice_command`, START 등)을 주는 걸로 확인돼
지금은 안 씁니다**(6일차 v55/v56 회신). 삭제하지 않고 남겨둔
이유는 팀원 쪽 분류기에 장애가 생겼을 때 폴백 경로로 되살릴 수
있게 하기 위해서입니다 — `OPENAI_API_KEY` 환경변수가 없어도
`tracking_node`/`voice_bridge_node`는 정상 동작합니다(이 모듈을
그 경로에서 호출하지 않으므로).

## 6. 노드 실행 순서 (launch 파일 없음, 수동 실행)

```
1. conveyor_node       (컨베이어 시리얼 연결 필요, 로봇/카메라 불필요)
2. usb_cam 노드         (C270, ros-jazzy-usb-cam 패키지 제공)
   ros2 run usb_cam usb_cam_node_exe --ros-args \
     -p video_device:=/dev/video2 -p image_width:=1280 \
     -p image_height:=720 -p pixel_format:=mjpeg2rgb -p framerate:=30.0
   (video_device 번호는 재부팅 시 바뀔 수 있음 — 4-4절 참고,
   /dev/v4l/by-id/ 경로 사용 권장)
3. tracking_node        (dry_run 파라미터로 로봇 실행 여부 제어,
                          camera.cam_to_base_path/belt_plane.abcd는
                          config/tracking.yaml 참고 — 캘리브레이션
                          안내.md에서 자세히 설명)
4. voice_bridge_node    (팀원 STT/TTS가 /voice_command를 발행하기
                          시작하면 아무 때나 띄워도 됨, 순서 안 중요)
```

**[전제]** dry_run=False(실제 로봇 실행)로 돌리려면 로봇 PC의
`dsr01` 컨트롤러 스택이 먼저 떠 있어야 합니다(별도 PC, 네트워크로
서비스 호출) — `~/ws_cobot_pjt/ws_dsr` 워크스페이스,
`ros2 launch m0609_rg2_bringup bringup.launch.py mode:=real
host:=192.168.1.100 model:=m0609`.

## 6-1. [신규 — 팀결정] YOLO는 Docker로 실행

`rocycle_robot/docker/`에 `Dockerfile`+`entrypoint.sh`+`README.md`가
있습니다 — GPU 없는 개발 PC에서 작성만 했고 **빌드/실행 검증은
관제 PC에서 처음 해야 합니다.** `docker/README.md`에 빌드·실행
명령과 미확인 체크리스트를 정리해뒀습니다. 컨테이너 안에서도
numpy/cv_bridge 충돌 방지 조치(numpy<2, opencv-python 미설치)가
그대로 필요합니다 — Docker가 이 문제를 자동으로 없애주지 않습니다.

## 7. 파라미터 오버라이드 참고 (테스트용)

```python
from rclpy.parameter import Parameter
TrackingNode(parameter_overrides=[
    Parameter("camera.cam_to_base_path", value="<T_cam2base.npy 경로>"),
    Parameter("belt_plane.abcd", value=[-0.003466, 0.005640, 0.999978, -316.7869]),
    Parameter("vision.dry_run", value=True),   # 로봇 없이 검출만 테스트
    Parameter("voice.initial_state", value="RUNNING"),  # 음성 없이 바로 Pick 테스트
])
```
`voice.initial_state`를 안 주면 기본값이 `IDLE`이라 `/voice_command`
로 `START`를 받기 전까지는 검출만 하고 Pick을 안 합니다(6일차
신규 동작 — 인수인계 문서 작성 시점 이후 추가된 내용이라 본문에
없습니다).
