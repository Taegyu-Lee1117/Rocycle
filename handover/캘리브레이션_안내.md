# 캘리브레이션 데이터 안내 — 반드시 읽을 것

**[중요] 아래 파일들은 사흘, 세 번의 실패 끝에 얻은 실측 데이터입니다.
새로 만들거나, "정리"한다고 고치거나, AI에게 "이 값이 이상해 보이니
다시 계산해줘"라고 시키지 마세요.** 그럴듯한 값으로 바뀌면 로봇이
엉뚱한 곳을 파지하러 갑니다 — 겉으로는 정상 동작하는 것처럼 보이다가
mm 단위로 계속 어긋나서, 원인을 못 찾고 오래 헤매게 됩니다.

---

## 1. 카메라 내부 파라미터 (intrinsics)

**[원문] 위치**: `rocycle_robot/config/tracking.yaml` 안에 리터럴
숫자로 박혀 있습니다(별도 파일 아님).

```yaml
camera.fx: 1427.528173
camera.fy: 1429.801911
camera.cx: 674.333213
camera.cy: 359.179031
camera.dist_coeffs: [0.083788, -0.006721, -0.005860, 0.007959, 0.0]
```

**Logitech C270 1개체 고유값입니다.** 카메라를 다른 개체로
바꾸면(같은 모델이라도) 이 값을 다시 캘리브레이션해야 합니다 —
개체마다 렌즈 편차가 있습니다.

## 2. 카메라→로봇 외부 변환 (eye-to-hand)

**[원문] 위치**: `rocycle_robot/calib_capture/T_cam2base.npy`
(numpy 4x4 동차변환행렬, `np.load()`로 읽음)

`tracking.yaml`의 `camera.cam_to_base_path`가 이 파일을 가리킵니다.

**[중요] 같은 폴더에 비슷한 이름의 파일이 여러 개 있는데, 이것만
쓰는 게 맞습니다:**
```
T_cam2base.npy                              ★이것만 사용(원문 확인)
T_cam2base_v1_taped_suspect.npy             ✗ 1차 실패작(솔버 버그, 157mm 오차)
T_cam2base_v2_belt_extrap_suspect.npy       ✗ 2차 실패작(깊이 다양성 부족)
T_cam2base_v3_belt_y_partial_suspect.npy    ✗ 3차 실패작(마운팅 재현성)
T_cam2base_corrected.npy                    ✗ 실사용 안 함(정확한 경위는
                                                실측기록.md 참고, 남겨둔
                                                이유는 "왜 이 값을 안 썼는지"
                                                설명 가능하게 하기 위함)
```
**파일명 끝에 `_suspect`가 붙은 건 "의심스러움/실패작"이라는 뜻으로
저희가 직접 붙인 표시입니다.** 지우지 말고 참고만 하세요 — 나중에
"왜 이 방법을 안 썼는가"를 설명해야 할 때 필요합니다(발표 평가
기준에 "설명 가능성"이 포함됨).

## 3. 벨트 평면 방정식

**[원문] 위치**: `rocycle_robot/config/tracking.yaml`
```yaml
belt_plane.abcd: [-0.003466, 0.005640, 0.999978, -316.7869]
```
평면 방정식 `ax+by+cz+d=0`의 계수(a,b,c,d)입니다. 5점 수동 티칭
결과(잔차 최대 0.334mm) — 원본 티칭 좌표는
`rocycle_robot/config/belt_plane_teach_points.py`에 있고, 이
파일 맨 위 주석에 재적합 방법이 적혀 있습니다.

## 4. 벨트 좌표 경험적 보정 (가장 놓치기 쉬움)

**[원문] 위치**: `rocycle_robot/rocycle_robot/geometry/
belt_correction.py` 안에 **코드로** 박혀 있습니다:
```python
_A = complex(1.650303241103378, 0.01761152097969898)
_B = complex(-197.71143039587997, 260.07775145570713)
```

**이건 코드가 아니라 데이터입니다.** 위 1~3번 캘리브레이션을
전부 거친 뒤에도 벨트 구간에서 예측이 체계적으로 눌리는 현상이
남아서, 실측 5점(펜 마킹)으로 최소자승 피팅한 평면 내 유사변환
(배율+회전+평행이동)입니다. 결과: **RMS 4.5mm, 최대 8.6mm 오차**
(이 이하 정밀도는 기대하지 마세요 — 파일 안에 `FIT_RESIDUALS_MM`
으로 명시돼 있습니다).

**AI가 이 파일을 "리팩터링"하면서 이 상수를 지우거나 "매직 넘버"
라고 바꾸려 하면 막아주세요.** 겉보기엔 그냥 숫자 두 개라 별
의미 없어 보이지만, 실측 데이터입니다.

**주의**: 이 보정은 벨트 평면 위 점에서만 검증됐습니다. 통 안쪽
등 다른 평면에 적용하려면 그 평면에서 따로 재보정해야 합니다.

## 5. 통(bin) 5개 티칭 좌표

**[원문] 위치**: `rocycle_robot/config/bin_teach_points.py`
(로봇 관절/TCP 좌표, 로봇 팔 기준이라 카메라 캘리브레이션과는
별개지만 마찬가지로 실측값이므로 손대지 마세요.)

## 6. 물리 배치 정보

**[전제, 불완전] 정식으로 촬영한 배치 사진은 없습니다.** 아래는
지금까지 실측/실행 과정에서 나온 참고 정보입니다 — 정확한 치수나
각도가 필요하면 로봇 팔 제어 담당과 화상으로 직접 확인하는 걸
권합니다.

```
카메라       Logitech C270, 벨트 위쪽 고정 카메라(eye-to-hand),
             해상도 1280x720, MJPEG 30fps 필수(YUYV는 7.5fps로
             제한됨 — 4-4절 알려진 함정)
로봇         두산 M0609, 벨트 옆에 위치, 홈 자세 J3=90°/J5=90°
그리퍼       OnRobot RG2, 로봇 TCP에 장착
벨트         컨베이어(스테퍼 구동), 100 steps/sec = 2.0cm/s 고정
통 5개       로봇 양옆 배치(plastic/can/paper/battery/review),
             정확한 좌표는 bin_teach_points.py 참고
```

`setup_photos/robot_belt_bins_example1.jpg`는 고정 카메라가 실제
파지 순간에 찍은 프레임 1장입니다 — 로봇 그리퍼, 벨트, 통 3개
(라벨 보임)가 한 화면에 잡힙니다. 정식 배치 사진은 아니지만
대략적인 구도 참고용으로 남겨둡니다.

**[중요] 이관 후 카메라나 벨트의 물리적 위치를 옮기면 위 1~4번
캘리브레이션이 전부 무효가 됩니다.** 옮겨야 한다면 캘리브레이션을
처음부터 다시 해야 하고, 이건 사흘이 걸린 작업입니다 — 꼭 필요한
게 아니면 위치를 그대로 유지하고 이관하세요.
