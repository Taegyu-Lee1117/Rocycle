## 0. 요약

고정 카메라(Logitech C270)와 로봇 좌표계를 정렬하는 eye-to-hand
캘리브레이션에서 **세 번 실패했습니다.**

| 시도 | 증상 | 원인 |
|---|---|---|
| 1차 | 목표 지점에서 **157mm** 벗어남 | 당시 진단: 회전 다양성 부족(4°) — **[정정] 사후 검증 결과 솔버 버그(5절)가 주된 원인이었을 가능성이 높음** |
| 2차 | 육안상 통과, 그러나 벨트 구간에서 **8~23cm** 오차 | 솔버 버그(5절) + 깊이 다양성 부족(66mm), 두 가지가 동시에 있었음 |
| 3차 | 깊이를 넓혔으나 **오히려 악화** | 체커보드 마운팅 재현성 한계 |

최종적으로 **실측 기반 경험적 보정**으로 RMS 4.5mm를 확보했습니다.

과정에서 **corecode의 캘리브레이션 솔버 자체에 버그**가 있다는
것도 발견했습니다.

## 1. 배경 — 왜 이 캘리브레이션이 필요한가

### 1-1. 두 종류의 캘리브레이션

| | 내부 캘리브레이션 | 외부 캘리브레이션 |
|---|---|---|
| 재는 것 | 렌즈와 센서의 성질 | 카메라와 로봇의 위치·자세 관계 |
| 결과 | 초점거리, 중심점, 왜곡계수 | 4×4 변환 행렬 |
| 카메라를 옮기면 | 변하지 않음 | **변함** |

**두 개가 모두 있어야 화면 픽셀을 로봇 좌표로 바꿀 수 있습니다.**

```
화면 픽셀 (u, v)
  ↓ 내부 캘리브레이션
카메라 기준 광선 방향
  ↓ 외부 캘리브레이션
로봇 기준 광선 방향
  ↓ 벨트 평면과 교차
로봇 기준 3D 좌표
```

### 1-2. 왜 자로 재면 안 되는가

카메라 위치 세 개(x, y, z)는 자로 잴 수 있습니다.
**그런데 자세 세 개(회전)를 못 잽니다.**

**1도 오차가 40cm 거리에서 약 7mm 위치 오차**를 만듭니다.
눈으로도 각도기로도 그 정밀도가 안 나옵니다.

그래서 **체커보드를 그리퍼에 붙이고 로봇을 여러 자세로 움직여**,
"로봇이 아는 자기 위치"와 "카메라가 본 체커보드 위치"를 대조해
변환을 역산합니다.

## 2. 1차 실패 — 회전 다양성 부족

### 2-1. 증상

캘리브레이션 후 로봇을 목표 좌표로 보냈더니 **약 157mm** 벗어났습니다.

### 2-2. 조건

```
샘플 수      9장
회전 다양성   약 4°
```

### 2-3. 원인

캘리브레이션은 **여러 자세에서 얻은 관측을 연립해 푸는 문제**입니다.
자세가 비슷하면 방정식이 서로 독립적이지 않아 해가 불안정해집니다.

**회전 다양성 4°는 "거의 같은 자세를 9번 찍은 것"과 다르지
않습니다.**

### 2-4. 대응

회전 범위를 **42°**로 넓히고 샘플을 12장으로 늘렸습니다.

### 2-5. 교훈

**샘플 수보다 자세 다양성이 중요합니다.**
같은 자세를 100장 찍어도 정보량은 1장과 같습니다.

### 2-6. [정정 — 사후 검증] 1차 실패의 진짜 원인은 회전 다양성이
아니었을 가능성이 높다

**5절에서 솔버 버그를 발견한 뒤, 1차의 9샘플 데이터를 그대로
`cv2.calibrateHandEye()`(수정된 알고리즘)로 다시 계산해봤습니다.**

```
1차 데이터(9샘플, 회전다양성 4°) + 수정 알고리즘
  → 카메라 기울기 38.09°

2차 데이터(12샘플, 회전다양성 42°) + 수정 알고리즘
  → 카메라 기울기 38.35°
```

**두 값이 거의 같습니다(0.26° 차이).** 회전 다양성이 부족했던
1차 데이터로도, 다양했던 2차 데이터로도 수정된 알고리즘으로는
같은 답이 나온다는 뜻입니다.

**즉 1차의 157mm 오차는 회전 다양성 부족이 아니라, 애초에 버그가
있던 솔버로 계산했기 때문이었을 가능성이 높습니다.** 당시엔
솔버 버그를 몰랐기 때문에 "회전 다양성 부족"으로 오진단하고
2차로 넘어갔습니다 — 그 진단으로 회전 다양성을 넓힌 것 자체는
방향이 나쁘지 않았지만(2-4절), **1차 실패의 실제 원인 규명으로는
틀렸다는 것**을 여기 정정해 둡니다.

## 3. 2차 실패 — 깊이 다양성 부족

### 3-1. 증상

1차 수정 후 테이블 위 두 지점에서 **육안상 정확**하게 도달했습니다.
그래서 통과로 판단했습니다.

**그런데 벨트 위에서 정밀 측정하니 8~23cm 오차가 나왔습니다.**

### 3-2. 정밀 측정 방법 — 펜 마킹

육안 확인의 한계는 명확했습니다. **로봇이 목표에 정확히 도달할수록
그리퍼가 대상을 가려 눈으로 확인할 수 없습니다.**

그래서 **그리퍼에 펜을 물려 종이에 점을 찍는** 방식으로 바꿨습니다.

```
1. 체커보드(종이)를 벨트에 테이프로 고정
2. 카메라가 코너를 검출 → 좌표 산출
3. 로봇이 그 좌표로 이동해 펜으로 마킹
4. 로봇이 물러난 뒤 코너와 마킹 사이 거리를 측정
```

**로봇이 물러난 뒤에 재므로 가림 문제가 사라집니다.**
그리고 여러 지점을 한 장에 찍으면 오차 패턴이 그림으로 남습니다.

### 3-3. 원인 규명 — 거리 보존 검산

실측 데이터에서 결정적 단서가 나왔습니다.

```
코너0  예측 좌표 x = 328.89
코너9  예측 좌표 x = 464.64
       → 예측상 거리 135.75mm

실제   9칸 × 25mm = 225mm
       → 비율 0.60
```

**여기서 중요한 판단이 나왔습니다.**

> **회전과 평행이동은 거리를 보존한다.**
> 실제로 225mm 떨어진 두 점은 어떤 좌표계로 변환해도 225mm다.
> 따라서 이 배율 오차는 회전 잔차로 설명할 수 없다.

이 논리 하나로 **세 번째 재캘리브레이션 시도를 멈추고** 다른
원인을 찾기 시작했습니다.

### 3-4. 개별 후보 검증 — 전부 정상

| 후보 | 검증 결과 |
|---|---|
| 단위 혼용 (mm/m) | 정상 |
| 변환 방향 뒤집힘 | 정상 (카메라 위치 실측 대조로 확인) |
| 평면 거리 계산 | 정상 (회전행렬 직교성 확인, det=1) |
| 왜곡 보정 순서 | 무관 (중심부라 영향 없음) |
| 체커보드 칸 크기 | 실측 24mm, 4% 차이로 40% 오차 설명 불가 |

**모든 후보가 정상인데 오차는 그대로였습니다.**

### 3-5. 결정적 단서 — 압축 비율이 거리에 따라 변한다

타겟 평면의 카메라로부터 거리를 바꿔가며 배율을 계산해 봤습니다.

```
z = 600mm  → 0.19
z = 319mm  → 0.60  (벨트)
z = 100mm  → 0.93
```

**멀수록 심하게 압축됩니다.** 이것이 깊이축 정확도 문제를 가리켰습니다.

### 3-6. 진짜 원인 — 체커보드 오프셋 일관성 검사

각 샘플에서 **"체커보드와 그리퍼 사이의 오프셋"**을 역산했습니다.
이것은 고정된 물리량이므로 **모든 샘플에서 같은 값이 나와야 합니다.**

```
X 방향  표준편차 1.9mm   정상
Y 방향  표준편차 1.0mm   정상
Z 방향  표준편차 7.7mm, 최대 28mm 벌어짐   ← 비정상
```

**깊이축만 일관성이 없었습니다.**

원인은 **12샘플의 깊이 범위가 66mm로 좁았던 것**입니다.
회전 다양성은 42°로 충분했지만, **카메라로부터의 거리 변화가
거의 없어 깊이축 정확도가 잡히지 않았습니다.**

그리고 캘리브레이션 샘플이 커버하지 못한 영역(벨트)에서 이 오차가
증폭되어 나타났습니다.

## 4. 3차 실패 — 마운팅 재현성 한계

### 4-1. 시도

깊이 범위를 **340~445mm(105mm)**로 넓혀 재촬영했습니다.

### 4-2. 결과 — 오히려 악화

```
오프셋 표준편차: 22.7 / 9.9 / 56.5mm
```

이전(1.9 / 1.0 / 7.7mm)보다 훨씬 나빠졌습니다.

### 4-3. 원인

**체커보드를 테이프로 다시 붙일 때마다 물리적 위치가 미묘하게
달라졌습니다.**

캘리브레이션은 "체커보드가 그리퍼에 고정되어 있다"를 전제합니다.
그런데 **테이프 마운팅의 재현성이 수 mm 수준**이라, 우리가 요구하는
정밀도에서는 그 자체가 오차원이 되었습니다.

### 4-4. 근본 해결책과 한계

**강성 마운트(3D 프린트 지그 등)가 필요합니다.**
당일 준비가 되어 있지 않아 보류했습니다.

## 5. 별도로 발견한 것 — 솔버 알고리즘 버그

캘리브레이션을 반복하는 과정에서, 제공된 참고 코드
(`corecode/eye2hand_calibration.py`)의 커스텀 AX=XB 솔버 자체에
문제가 있다는 것을 발견했습니다.

### 5-1. 검증 방법

**정답을 아는 가상 데이터를 만들어 넣었습니다.**

실제 데이터로는 "결과가 이상한데 데이터 문제인지 코드 문제인지"
구분할 수 없습니다. 정답이 있는 입력을 넣으면 코드 자체를 검증할
수 있습니다.

### 5-2. 결과

```
커스텀 Calibrate()      회전 오차 94°, 위치 오차 908mm
cv2.calibrateHandEye()  오차 사실상 0
```

**커스텀 솔버는 완전히 틀린 값을 반환했습니다.**

### 5-3. 대응

`cv2.calibrateHandEye()`로 교체했습니다.

### 5-4. 다만 이것이 배율 문제의 원인은 아니었습니다

**이 버그를 고친 뒤에도 배율 문제가 그대로 남았습니다.**
회전·위치 오차를 만드는 버그였지, 거리를 압축하는 원인은
아니었습니다(3-3절 참고).

**두 문제가 겹쳐 있어 원인 규명이 어려웠습니다.**

## 6. 최종 대응 — 실측 기반 경험적 보정

### 6-1. 방법

마운팅 문제를 당일 해결할 수 없어, **캘리브레이션 결과를 그대로
쓰되 실측으로 보정**하는 방식을 택했습니다.

```
펜 마킹으로 확보한 그라운드트루스 5개 점에
평면 내 유사변환(배율 + 회전 + 평행이동, 4자유도)을
최소자승 피팅
```

### 6-2. 결과

```
RMS 잔차   4.5mm
최대 잔차   8.6mm
배율       1.65배  ← 3-3절에서 발견한 압축비 0.61의 역수와 일치
회전       0.61°   ← 매우 작음
```

**회전이 거의 0이라는 것은, 문제가 순수한 축척 오차에 가까웠다는
뜻입니다.** 3-3절의 거리 보존 검산이 가리킨 방향과 일치합니다.

### 6-3. 재검증

무작위로 고른 코너 5곳에서 다시 측정해 **0~4mm 오차**로 재현을
확인했습니다.

### 6-3a. [확인] 잔차에 위치별 경향성이 있는가 — 뚜렷하지 않음

피팅에 쓴 5점의 잔차를 벨트 길이 방향(raw x) 순으로 나열:

```
x=266.7  잔차 4.48mm
x=312.9  잔차 8.62mm
x=321.7  잔차 1.67mm
x=366.9  잔차 2.12mm
x=412.0  잔차 1.26mm
```

거리(x)와 잔차의 상관계수는 -0.55로 약한 음의 상관은 있으나,
**5점만으로는 통계적으로 신뢰하기 어렵고 뚜렷한 단조 경향은
보이지 않습니다.** 유사변환(4자유도)이 부족해서 배율이 위치마다
달라야 한다는 가설은, 적어도 이 5점 범위 안에서는 강하게
뒷받침되지 않습니다 — 다만 점 수가 적어 결론을 내리기엔
이릅니다. 점을 더 찍어 재확인할 필요가 있습니다.

### 6-3b. [주의] 최대 잔차가 건전지 크기 대비 작지 않다

```
건전지(AA) 반지름       7mm
최대 잔차               8.6mm  ← 반지름보다 큼
RMS 잔차                4.5mm  ← 반지름의 64%
```

**최대 잔차(8.6mm)가 건전지 반지름(7mm)보다 큽니다.** 즉 최악의
경우 예측 좌표가 건전지 몸통 바깥을 가리킬 수 있다는 뜻입니다.
RMS(4.5mm, 전형적인 경우)도 반지름의 절반을 넘어 여유가 크지
않습니다. **건전지 파지를 시도하기 전에 실측으로 성공률을
확인하거나, 점을 더 찍어 정밀도를 높이는 작업이 필요합니다**
(캔·페트병처럼 큰 물체는 이 수준의 오차로도 문제없을 가능성이
높습니다).

### 6-4. 한계 — 이 보정은 벨트 평면 전용입니다

**다른 평면(통 안쪽 등)에 그대로 쓸 수 없습니다.**

근본 원인이 캘리브레이션의 깊이축 부정확이므로, **평면마다 다른
크기로 나타날 수 있습니다.** 다른 평면에서 좌표를 산출할 일이
생기면 그 평면에서 별도로 재보정해야 합니다.

### 6-5. [명시] 이것은 근본 해결이 아니라 증상 상쇄입니다

**캘리브레이션의 깊이축 오차 자체(3-6절)를 고친 것이 아닙니다.**
그 오차가 벨트 평면 위에서 만드는 결과(예측 좌표의 압축)를
실측으로 되돌려놓은 것입니다. 근본 해결은 강성 마운트로 재캘리브
레이션하는 것이고(4-4절), 오늘은 그게 준비되지 않아 이 방법을
썼습니다.

**발표·문서에서 "캘리브레이션을 정확히 했다"고 쓰지 않습니다.**
정확한 표현: *"캘리브레이션에 남은 깊이축 오차를 실측 기반
보정으로 상쇄했다. 근본 해결에는 강성 마운트가 필요하다."*

## 7. 교훈

### 7-1. 캘리브레이션 샘플은 "실제 사용 영역"을 감싸야 한다

회전 다양성만으로는 부족합니다. **위치와 깊이도 실제로 좌표를
산출할 영역을 브래킷(bracket)해야 합니다.**

1차는 회전이, 2차는 깊이가 부족했습니다.

### 7-2. 정성적 확인은 실패를 놓친다

2차 캘리브레이션은 **육안으로는 정확해 보였습니다.**
정밀 측정을 하고서야 8~23cm 오차가 드러났습니다.

**"눈으로 보니 맞는 것 같다"는 검증이 아닙니다.**

### 7-3. 강체 변환은 거리를 보존한다

**회전과 평행이동은 두 점 사이 거리를 바꾸지 못합니다.**

배율이 어긋났다면 그것은 캘리브레이션(강체 변환)이 아니라 **다른
곳**의 문제입니다. 이 판단 하나가 세 번째 삽질을 멈추게 했습니다.

### 7-4. 정답을 아는 데이터로 코드를 먼저 검증한다

실제 데이터로는 "데이터 문제인지 코드 문제인지" 구분할 수 없습니다.
**가상의 정답 데이터를 넣어보면 코드 자체를 검증할 수 있습니다.**

이 방법으로 솔버 버그를 찾았습니다.

### 7-5. 물리적 마운팅도 오차원이다

소프트웨어를 아무리 정확히 해도 **체커보드가 테이프로 붙어 있으면
그 재현성이 정밀도의 상한**이 됩니다.

정밀 캘리브레이션에는 강성 마운트가 필요합니다.

### 7-6. 원인이 여러 개일 수 있다

솔버 버그와 깊이 다양성 부족이 **동시에** 있었습니다.
하나를 고쳐도 증상이 남아 있었고, 그 때문에 원인 규명이 지연됐습니다.

**"고쳤는데 여전하다"는 것이 곧 "그게 원인이 아니다"는 뜻은
아닙니다.** 다른 원인이 함께 있을 수 있습니다.

## 8. 벨트 물리 이동 — 원위치 복원 후 재검증 완료

3일차 후반 반복 시행 중 벨트 위치가 이동한 것이 확인됐습니다.
`belt_plane`과 보정값 모두 이동 전 위치를 전제로 구했으므로
재검증이 필요했습니다.

**벨트를 원위치로 복원한 뒤 무작위 코너 1곳으로 재검증한 결과,
오차 약 2.2mm(세로 2mm/가로 1mm)로 이동 전(0~4mm대)과 동등한
정확도를 확인했습니다.** `belt_plane`/보정값 모두 재작업 없이
그대로 유효합니다.

**[주의] 이건 검증 1회일 뿐입니다.** 벨트를 다시 만지거나
시연 직전 재배치하는 경우, 매번 이 정도로 정확히 복원된다는
보장은 없습니다 — 9절 남은 과제(벨트 물리 고정)가 이 문제의
근본 해결책입니다.

## 9. 남은 과제

**1) 벨트 물리 고정.** 지금까지 벨트가 제자리에 있다고 암묵적으로
가정해 왔는데, 실제로 밀렸던 적이 있습니다. 클램프나 볼트 고정
등으로 벨트 자체를 테이블에 물리적으로 고정해야 이 문제가
재발하지 않습니다 — **시연 중 벨트가 밀리면 그날 시연 전체가
무효가 될 수 있습니다.**

**2) 캘리브레이션 품질 사전 판정 절차 도입.** 3-6절의 "체커보드-
그리퍼 오프셋 역산 표준편차" 검사를, 캘리브레이션 직후·실측
전에 항상 돌리는 절차로 등록합니다. 이 검사가 있었다면 2차
캘리브레이션의 문제(Z축 7.7mm)를 실측 전에 걸러냈을 것입니다.

**3) 건전지 파지 전 정밀도 재확인.** 6-3b절 — 최대 잔차(8.6mm)가
건전지 반지름(7mm)보다 큽니다. 점을 더 찍어 정밀도를 높이거나,
실제 파지 시도로 성공률을 먼저 확인할 것.
