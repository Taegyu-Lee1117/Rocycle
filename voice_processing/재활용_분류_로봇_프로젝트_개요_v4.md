# 컨베이어 기반 재활용 분류 협동로봇 — 프로젝트 개요 (v4)

> 팀 공유용 · 제출물 아님

---

## 1. 시스템 개요

컨베이어로 흘러오는 재활용 쓰레기를 로봇팔이 추적해서 집고, 종류별로
분류합니다. 카메라로 볼 수 없는 정보는 힘 센서로 알아내고, 로봇이
처리할 수 없는 것은 사람이 확인하도록 따로 모읍니다.

**분류 통 6개**

```
플라스틱 / 캔 / 종이 / 건전지 / 비닐 / 확인 필요
```

앞의 다섯은 **재질별 분류**이고, 마지막 하나는 **처리 상태별 분류**
입니다. 로봇이 판단은 했으나 스스로 처리할 수 없는 것들이 여기 모입니다.

벨트 끝 아래에는 **일반쓰레기통**이 있습니다. 로봇이 집지 않은 물체는
그대로 흘러가 여기로 떨어집니다.

---

## 2. 왜 로봇팔이 해야 하는가

재활용 선별장은 지금도 사람이 맨손으로 일하는 공간입니다.

깨진 유리나 찢어진 캔에 손을 베는 게 흔한 재해고, 음식물이 남은 용기를
직접 만져야 합니다. 악취와 분진이 상시 발생하고, 같은 동작을 하루 수천
회 반복하면 판단 정확도가 떨어집니다.

**그런데 완전 자동화는 성립하지 않습니다.**

페트병 라벨을 떼는 건 로봇이 물리적으로 할 수 없고, 묶인 비닐 안에
무엇이 들었는지는 어떤 센서로도 알 수 없습니다.

그래서 만들려는 건 사람을 대체하는 로봇이 아닙니다.
**대부분은 스스로 처리하되, 자기가 할 수 없는 일을 인지하고 사람에게
넘기는 로봇**입니다.

## 3. 핵심 아이디어

**"보이지 않는 것을 다른 방법으로 알아낸다"**

| 알아내야 하는 것 | 담당 | 왜 |
|---|---|---|
| 물체 종류 | 고정 카메라 | 비전으로 충분 |
| 벨트 위 위치 추적 | 고정 카메라 | 로봇이 움직여도 시야가 고정됨 |
| **캔 안에 음료가 남았는가** | **힘 센서 (무게)** | **알루미늄이라 원리적으로 불가** |
| 묶인 비닐 안의 내용물 | **판별 불가** | 사람이 확인 |
| 사람이 가져가려는 의도 | 순응 제어 | 당기는 힘 또는 변위 감지 |

### 캔을 왜 무게로 재는가

빈 캔과 음료가 남은 캔은 겉으로 구분되지 않습니다. 알루미늄이라
안이 전혀 안 보이니까요.

재활용 선별장에서 쓰는 산업용 적외선 분류기는 1000~1700nm 대역을
씁니다. 저희 카메라는 850nm이고, **금속은 어떤 파장으로도 통과하지
못합니다.**

그래서 **집어 들고 무게를 잽니다.** 빈 캔 15g, 음료가 남으면 300g이
넘습니다.

### 묶인 비닐은 유일하게 판별할 수 없습니다

실제로 비닐봉지 안에 쓰레기를 담아 버리는 경우가 많습니다.
겉으로는 무엇이 들었는지 알 수 없습니다.

**무게로도 안 됩니다.** 비닐 자체가 가벼워 내용물이 있어도 임계값을
못 넘길 수 있고, 반대로 옷가지처럼 재활용 가능한 것이 들어도 무겁게
나옵니다.

**비전으로도 무게로도 판별할 수 없는 유일한 품목**이라, 사람 확인이
필연입니다.

## 4. 대상 품목 6종

| 클래스 | 품목 | 목적지 |
|---|---|---|
| `can` | 알루미늄 캔 | 캔 통 (내용물 있으면 확인 필요 통) |
| `pet_labeled` | 페트병 (라벨 있음) | **사람에게 전달** |
| `pet_unlabeled` | 페트병 (라벨 없음) | 플라스틱 통 |
| `paper` | 종이팩 | 종이 통 |
| `battery` | 건전지 (AA) | 건전지 통 |
| `vinyl` | 묶인 비닐 | **확인 필요 통** |

**학습하지 않은 물체**(뭉친 종이, 휴지심 등)는 검출되지 않고 그대로
흘러가 일반쓰레기통으로 떨어집니다.

### 준비 시 주의

- 캔은 **미개봉 캔**으로 무게 조건을 재현합니다. 물을 넣어 밀봉하는
  것보다 안정적입니다
- 라벨 있는 페트병과 없는 페트병은 **다른 병**을 쓰세요. 같은 병에서
  라벨을 떼면 자국이 남습니다
- 비닐은 **확실히 묶인 것**만 씁니다. 반쯤 뭉친 중간 상태는 클래스
  경계를 흐립니다
- 건전지는 AA 기준입니다. 화면에서 폭 30픽셀로 검출에 충분합니다

## 5. 전체 시나리오

### 준비

컨베이어 위에 여러 종류의 쓰레기를 올려둡니다. 로봇 주변에 분류 통
6개를, 벨트 끝 아래에 일반쓰레기통을 배치합니다.

고정 카메라는 벨트를 30~40도 각도로 내려다보고, 손목 카메라는 로봇과
함께 움직입니다.

### 시작

작업자가 말합니다. **"분리수거 시작해줘"**

벨트가 초당 2cm로 돌기 시작하고 로봇이 대기 자세로 이동합니다.

### 기본 흐름

고정 카메라가 흘러오는 물체를 발견하고 **끝까지 추적**합니다.

로봇이 **물체가 도착할 위치를 미리 계산해** 그 지점에서 집습니다.
벨트가 계속 움직이므로 현재 위치가 아니라 집는 시점의 위치로 갑니다.

집은 뒤에는 **고정된 측정 자세로 이동해 정지**합니다. 여기서 무게를
재고, 손목 카메라로 제대로 잡혔는지 확인합니다.

종류에 맞는 통에 넣고 처리 기록을 남긴 뒤 다음 물체로 넘어갑니다.

### 분기 A — 캔 (무게 측정)

캔은 안이 안 보이므로 무게를 잽니다.

**가벼우면** 캔 통으로 갑니다.
**무거우면** 음료가 남았다는 뜻이므로, 로봇이 이렇게 말하고
확인 필요 통으로 보냅니다.

> "내용물이 남아 있습니다. 확인 필요 통으로 보냅니다."

### 분기 B — 묶인 비닐

안에 무엇이 들었는지 알 수 없으므로 확인 필요 통으로 보냅니다.
무게 측정은 하지 않습니다. 재도 판별되지 않기 때문입니다.

> "내용물을 확인할 수 없어 확인 필요 통으로 보냅니다."

### 분기 C — 라벨 붙은 페트병 (사람에게 전달)

라벨은 떼고 배출해야 하지만 로봇은 할 수 없습니다.

로봇이 집어 든 상태로 사람이 받기 좋은 위치에 **정지**하고 말합니다.

> "이 페트병은 라벨을 제거해야 합니다. 받아 가시겠어요?"

**순응 제어 모드로 전환**합니다. 외부에서 힘을 가하면 팔이 부드럽게
따라 움직여 사람이 다가와도 안전합니다.

작업자가 페트병을 잡고 당기면 **로봇이 그것을 감지해** 그리퍼를 엽니다.
사람이 오지 않으면 확인 필요 통으로 보내고 다음 작업을 계속합니다.

### 작업 중 음성 개입

| 발화 | 동작 |
|---|---|
| "잠깐 멈춰" / "다시 시작해" | 일시 정지·재개 |
| "지금까지 몇 개 처리했어?" | 처리 현황 보고 |
| "그만하자" | 작업 종료 |

### 종료

로봇이 현재 동작을 마치고 홈 위치로 복귀한 뒤 결과를 보고합니다.

> "분리수거 작업을 종료합니다.
>
> 총 열두 건을 처리했습니다.
> 플라스틱 넷, 캔 셋, 종이 둘, 건전지 하나, 일반쓰레기 둘입니다.
>
> 확인 필요 통에 셋 들어갔습니다."

0건인 문단은 통째로 생략합니다.

## 6. 사람 개입은 한 번뿐입니다

**실시간으로 사람을 부르는 건 라벨 페트병 하나입니다.**

나머지는 확인 필요 통에 모아두고 작업이 끝난 뒤 한 번에 알립니다.
**로봇이 작업을 자주 중단시키지 않는다**는 것이 이 설계의 의도입니다.

## 7. 포함되는 기능

### 인식

- 6종 물체 판별
- **움직이는 물체의 지속적 추적**
- **도착 위치 예측** — 로봇 이동 시간을 고려해 집을 시점의 위치를 계산
- 카메라 두 대의 역할 분담 — 멀리서 계획하고, 가까이서 확인

### 힘 기반 제어

- **무게 측정** — 캔 안의 내용물 유무 판별
- **순응 제어 사람 전달** — 사람이 당기는 것을 감지해 넘겨줌
- **품목별 파지력** — 캔은 찌그러지지 않게, 미끄러지지 않게
- 과도한 힘 감지 시 즉시 정지

### 안전

**사람 안전을 네 겹으로 막습니다.**

```
1층  작업 영역 분리 — 정상 흐름에서 사람 손이 벨트 위에 있을 이유가 없음
2층  손 검출 시 사이클 정지 — 배경 차분으로 "예상 품목이 아닌 큰 이물체"를 감지
3층  파지 직전 재확인
4층  힘 하드리밋 — 비전이 전부 실패해도 작동
```

**인식에 의존하지 않는 최종 방어선이 있다**는 것이 핵심입니다.

그리고 로봇이 부딪히면 안 되는 구조물(벨트, 통, 카메라 마운트)을
좌표로 정의해두고, 목표 지점이 그 안에 들어가면 명령을 거부합니다.

### 음성

- 작업 시작 · 정지 · 재개 · 종료
- 처리 현황 질의응답
- 판정 사유를 그 순간에 안내
- 작업 결과 요약 보고

### 예외 처리

- 검출 실패 시 재시도 후 통과
- 파지 실패 시 재시도 2회 후 다음 물체
- 판정이 애매하면 확인 필요 통으로 (자동 처리하지 않음)
- 모든 처리 이력을 DB에 기록

## 8. 하드웨어 구성

**PC 2대 구성**

```
[관제 PC]                    [로봇 PC]
 고정 카메라 (벨트 감시)        손목 카메라
 물체 추적                     로봇 제어
 컨베이어 제어                 상태 머신 / 정책 / 음성
```

관제 PC가 컨베이어를 맡는 이유는 **손 검출 시 벨트를 즉시 세우기
위해서**입니다. 판단하는 노드와 정지시키는 노드가 같은 PC에 있으면
네트워크를 거치지 않습니다.

| 구성 | 내용 |
|---|---|
| 로봇 | 두산 M0609 |
| 그리퍼 | OnRobot RG2 |
| 고정 카메라 | Logitech C270 웹캠 (RGB만) |
| 손목 카메라 | Intel RealSense |
| 컨베이어 | 아두이노 스테퍼 제어, 103cm × 7cm, 초당 2cm 고정 |
| 분류 통 | 6개 + 벨트 끝 일반쓰레기통 |
| DB | PostgreSQL |

## 9. 지금까지 확인된 것

| 항목 | 결과 |
|---|---|
| 그리퍼 ROS2 제어 | **가능.** 기존 패키지로 충분 |
| 힘 센서 노이즈 | Fz 변동폭 1.01N. 기존 전제(±2N)보다 작음 |
| 무게 측정 | **통과.** 빈 것과 든 것 차이가 노이즈의 4.6배 |
| 벨트 속도 | 초당 2.0cm. 이론값과 2% 차이 — 탈조·미끄러짐 없음 |
| 벨트 응답 | 기동 13.8ms / 정지 8.5ms |
| 카메라 내부 캘리브레이션 | 완료. 재투영 오차 0.78px |
| 벨트 평면 정의 | 완료. 잔차 최대 0.334mm |
| 좌표 정렬 (카메라↔로봇) | **1차 실패 후 재작업으로 통과** |
| 순응 제어 변위 | 36.8mm까지 안전 정지 없이 도달 |

**좌표 정렬 실패가 좋은 교훈이었습니다.** 9샘플에 회전 다양성이 4°뿐일
때는 157mm나 틀렸고, 12샘플에 42°로 넓히니 통과했습니다. **샘플 수보다
자세 다양성이 결정적**이라는 걸 실측으로 확인했습니다.

## 10. 남은 과제

### 확인 중

**좌표 정확도를 mm로 재는 것**이 가장 급합니다. 지금은 "육안상 정확"
까지만 확인됐는데, 그게 2mm인지 10mm인지에 따라 건전지(지름 14mm)를
잡을 수 있는지가 갈립니다.

그리퍼에 펜을 물려 종이에 점을 찍는 방식으로 잽니다. 로봇이 물러난
뒤에 재면 되니 가림 문제가 없습니다.

**통 티칭**도 남았습니다. 관절 가동 범위가 물리적 한계보다 좁게
설정되어 있어(J2가 ±95°), 통 6개가 전부 도달 범위에 들어오는지
확인해야 합니다.

**무라벨 페트병 검출**이 될지 미확인입니다. 웹캠에 깊이 정보가 없어
투명체 검출이 원리적으로 제한됩니다. 학습 후 검출률을 보고 판단합니다.

**PC 물리 분리**가 아직입니다. 통합 작업 전에 통신 검증까지 마쳐야
합니다.

### 알려진 제약

**순응 제어 중 안전 정지**가 세 번 중 두 번 발생한 적이 있습니다.
원인은 미확정이고, 힘 대신 위치 변화로 감지하는 방식으로 대응합니다.
9일차 리허설에서 10회 연속 무사고여야 시연에 포함합니다.

**컨베이어를 입체 구조물로 취급하지 못해** 그리퍼가 벨트를 누른 적이
있습니다. 구조물 좌표를 정의하는 것으로 대응했습니다.

## 11. 단계별 목표

실제 개발이 5일이라 단계를 나눴습니다.
**어느 단계에서 멈추더라도 완결된 시스템이 되도록** 잘랐습니다.

| 단계 | 내용 |
|---|---|
| **1단계 (필수)** | 벨트 정지 상태에서 인식 · 파지 · 무게 측정 · 분류 완주 |
| **2단계 (핵심)** | 벨트 가동, 추적 및 예측 파지 + 순응 제어 사람 전달 |
| **3단계 (확장)** | 두 카메라 상호 검증, 무라벨 페트병 검출 |

## 12. 데이터셋

- 고정 카메라용 **6클래스**, 클래스당 60~70장
- **손으로 직접 라벨링합니다.** 자동 라벨링 도구를 쓰지 않는 것은
  의도적 선택입니다
- 촬영은 실제 운용과 같은 조건에서 — 같은 카메라, 벨트, 조명, 거리
- **학습과 검증은 영상 단위로 나눕니다.** 영상에서 뽑은 프레임은
  인접한 것끼리 거의 같아서, 무작위로 나누면 성능이 실제보다 높게
  나옵니다

### 공개 데이터를 쓰지 않는 이유

AI-Hub 재활용 데이터셋을 받아 열어봤습니다. **한 프레임에 여러 재질이
섞여 있는데 대상 클래스 하나만 라벨링되어 있어**, 그대로 쓰면 실제로
존재하는 물체를 배경으로 학습하게 됩니다.
