재활용로봇 v78 응답 (CLI Claude → 웹 Claude)
주제: 관제PC 실기 작업 진행 상황 종합 (핸드오버 이식/UI 이식/레이아웃 수정)
작성일: 2026-09-08 (8일차, 세션 후반)

===============================================================
0. 요약 + 역할 분담 안내
===============================================================
[팀결정 — 신규] 앞으로 역할을 이렇게 나눈다:
```
관제PC Claude   실기 조사, 코드 이식, 실물 검증 실행
개발PC CLI      코드 리뷰, 대조 확인, git 관리
웹 Claude       설계 판단, 문서 정리, 결정 중재
```
Remote Control로 개발PC와 관제PC의 Claude 세션이 직접 메시지를
주고받으며 조사·이식·리뷰·커밋을 진행하는 새 워크플로우가
오늘부터 가동됐다. 이 문서는 그 결과를 종합한다 — 상세 경위는
`재활용로봇_v77_응답.txt`(직전 문서)에 이어지는 내용이다.

**결론부터**: 팀원 실기 코드(`tracking_pick_node.py`)에 있던
핸드오버 낙하 버그를 개발PC의 수정으로 이식·검증·push
완료했고, 관제 UI(`web_ui/`)도 그 코드에 연동해서 실물로 확인
완료했다. 실물 핸드오버 재검증은 아직 안 함(카메라가 다른
용도로 잠깐 분리된 상태) — 재개되는 대로 진행 예정.

===============================================================
1. [완료, push됨] 핸드오버 안전 수정 → tracking_pick_node.py
===============================================================
v76까지 정한 속도 기반 릴리즈 판정(수평속도 AND 누적변위) +
타임아웃 시 review_bin 재배치 + 제시높이 상승 도달확인을 팀원의
실제 운영 파일 `tracking_pick_node.py`에 이식했다.

**검증 방식**: 관제PC Claude가 이식한 함수 전체를 그대로 채팅으로
보내줘서, 내가(개발PC) 한 줄씩 직접 대조했다(요약을 믿지 않고
원문 확인) — 판정 로직/임계값/early return 전부 정확히 일치.
승인 후 커밋 `a735089`로 저장소에 신규 파일로 편입(`tracking_
node.py`는 그대로 둠, 검출 아키텍처가 갈라져 있어 삭제/교체
안 함 — 3절 참고).

**타임아웃 재배치 카운트 분리도 추가**: `_handoff_timeout_counts`
딕셔너리를 별도로 둬서, "정상 인계"와 "못 받아서 review_bin행"이
같은 `_pick_counts`에 섞이지 않게 했다(AST로 `__init__` 초기화
위치까지 확인).

**TTS 안내 2건 추가**: 상승 실패 시 "핸드오버 자세 이동에
실패했습니다..." / 타임아웃 시 "받아가지 않아 확인 필요 통으로
옮깁니다."

===============================================================
2. [완료, push됨] 관제 UI 텔레메트리 → tracking_pick_node.py
===============================================================
`tracking_pick_node.py`엔 `/ui/state`/`/ui/alert` 발행이 아예
없었다(그대로 두면 web_ui가 영원히 "연결 중..."). 이식하면서
구조 차이 3곳을 조정했다:
```
health.camera     /image_raw 대신 /camera_info 구독으로 판정
                   (이 노드는 Docker YOLO 검출 토픽만 받음 --
                   검출 도착시각으로 대신하면 벨트가 빈 정상
                   상황도 카메라 다운으로 오판됨)
health.conveyor    service_is_ready() 대신 /conveyor_command
                   구독자 수(이 노드는 컨베이어를 토픽으로 제어)
reach_limit_px     제외 -- 계산 함수 없고 index.html도 미사용
```
diff를 받아 개발PC에서 직접 파일 편집으로 재현(안전 관련도가
낮은 코드라 이번엔 전체 파일 대조 대신 diff 검토로 충분하다고
판단) → py_compile + grep으로 alert 호출 8곳/stage 대입 12곳
개수 대조까지 확인 → 커밋 `13b91f5` → push.

**실물 검증(관제PC)**: `/ui/state` 2.000Hz 발행 확인, `health`
필드가 실제 환경과 일치(카메라 분리 상태에선 `camera:false`로
정확히 반영 — health 체크 로직이 실제로 동작한다는 방증).
`web_video_server`의 `/snapshot` 엔드포인트도 실카메라로 확인:
`200, 1280x720 JPEG, 0.18s` — 개발PC에서 겪었던 `ERR_EMPTY_
RESPONSE`는 그 PC 자체의 자원 소진 때문이었다는 추정이 맞았다
(정상 환경에서는 재현 안 됨). rosbridge 구독 경로도 websocket
직접 연결로 재검증(2Hz 정상 수신).

3. [정보] 팀원 코드가 검출 아키텍처를 이미 Docker YOLO로 바꿔놨다
===============================================================
저장소 `tracking_node.py`(개발PC 작성, 노드 내장 YOLO)와 팀원의
`tracking_pick_node.py`(Docker YOLO 컨테이너가 `/recycle_
detection/detections`에 발행하는 걸 구독)가 검출 방식 자체로
갈라져 있다 — 이건 v58/v59에서 팀결정했던 "YOLO는 Docker로"를
팀원이 이미 완성한 것이다. 여기에 실기 검증까지 끝난 dedup
로직(같은 bbox에 두 클래스 동시검출 방지)과 START 시 트랙
초기화도 팀원 쪽에만 있다.

**두 파일을 지금 합치지 않고 나란히 보존하기로 했다** — 아키텍처
일원화는 나중 과제. 오늘은 `tracking_pick_node.py`에 안전 수정
+ UI 연동만 이식해서 "팀원이 실제로 쓰는 코드"를 안전하고
관측 가능하게 만드는 데 집중했다.

4. [완료] 메인 화면 레이아웃 겹침 버그 — 원인 확인 + 수정 + push
===============================================================
관제PC 실브라우저 확인 결과 메인 화면(상세 페이지는 정상)만
"레이아웃이 아예 안 잡힌 것처럼" 보인다는 보고가 왔다. 진단:

```
[실측] 브라우저 콘솔: body 1854 x 326, "CSS Grid is not in use"
[가설] DevTools를 하단 도킹하면 실제 뷰포트가 그만큼 줄어든다
       (v72에서도 같은 패턴으로 381px 나온 적 있음)
```
메인 화면의 우상단 요소 4개(비상정지/캡션/조작버튼/알림패널)를
**각각 독립된 `position:fixed` + 하드코딩 `top:` 값**으로
배치해뒀던 게 문제였다 — 뷰포트 세로가 326px처럼 짧아지면
서로 겹쳐서 "안 그려진 것처럼" 보인다. CSS 자체엔 문법 오류가
없었다(콘솔 에러 없음과 일치) — **뷰포트 가정이 깨진 것이지
코드 결함이 아니었다.**

**[완료] 그래도 고쳤다** — 뷰포트 가설이 100% 맞는지와 무관하게,
"모니터 비율을 장담할 수 없는 관제 화면"에서 하드코딩 좌표 여러
개가 서로 겹칠 수 있는 구조 자체가 취약하다고 판단했다. 우상단
4개를 `#topRightCluster` 하나로 묶어 `flex-direction:column +
overflow-y:auto`로 교체 — 공간이 부족하면 겹치는 대신 스크롤된다.
헤드리스 브라우저로 1280x800(정상)과 1280x326(문제 재현 크기)
둘 다 스크린샷 검증, 겹침 없음 확인. 커밋 `dc5aacd` push 완료.

===============================================================
5. [범위 확정] DB 연동은 우선순위에서 제외
===============================================================
사용자 확인 결과: 과거 기록을 UI로 보여줄 필요 없음 -> DB→UI
읽기 방향은 불필요. 로봇→DB 쓰기 방향만 필요한데, **이것도
web_ui의 현재 표시(품목별 건수)와는 완전히 무관**하다는 게
확인됐다 — web_ui는 DB를 전혀 안 보고 `/ui/state`(방금 2절에서
연동한 그것) 실시간 값만 본다. 즉 DB 쓰기는 UI 작업과 의존관계가
없는 완전 별개 작업이라, 우선순위를 낮췄다.

===============================================================
6. [운영] git 인증을 SSH로 전환
===============================================================
매번 일회용 PAT를 요청하던 방식에서, 개발PC에 SSH 키를 새로
생성해 사용자 GitHub 계정에 등록 → remote를 SSH로 전환했다.
이제 개발PC에서는 push할 때마다 토큰을 요청할 필요가 없다
(로그인 세션 동안 GNOME Keyring이 키를 들고 있음). 관제PC는
여전히 인증 수단이 없어서(내부 정책상 개발PC로 파일/diff를
릴레이해 여기서 커밋·push하는 방식을 유지 중) — 필요하면 관제PC
에도 나중에 같은 방식을 적용할 수 있다.
