 0. v42(J5 특이점) 재확인 결과 — 가설 기각
====================================================================

하드웨어 재연결 후 `get_current_posj()`로 모든 티칭 자세(5개 통
호버, 벨트 전/중/후단)의 J5를 직접 읽었다.

```
PAPER_hover     J5=89.6°   PLASTIC_hover  J5=95.3°
CAN_hover       J5=94.5°   BATTERY_hover  J5=113.6°
REVIEW_hover    J5=91.4°   BELT_front     J5=93.2°
BELT_middle     J5=96.6°   BELT_far       J5=69.4°
```

**전부 0°에서 멀리 떨어져 있어(69~114°) 손목 특이점(J5≈0)
조건에 해당하지 않는다.** battery_bin에서 HOME→호버→PLACE→상승
→HOME 전 구간을 재현했으나 매끄럽게 동작 — **관절이 튀는 현상도
재현 안 됨.** battery_bin은 기울임 없이 원래 좌표(수직 자세)로
확정, `bin_teach_points.py` 변경 불필요.

**J5 특이점 가설은 기각한다. 어제 관측된 "튐"은 원인 불명의
일회성 현상으로 종결.**

 1. 하강 시간 실측
====================================================================


(이동+하강+닫힘)에 필요한 세 항목 중 두 번째가 채워짐.

====================================================================
 2. [팀결정] can/paper 파지력 5N → 10N 상향
====================================================================

5N은 닫히는 속도가 너무 느리다고 판단, **약간의 찌그러짐은
감수하기로 하고 10N으로 상향**(속도 우선). `close_wait_sec`는
2.0초 유지. `config/gripper_profiles.yaml` 갱신 완료.

**[실측] 5N에서 close_wait_sec=2.0초가 실제로는 부족했던 사례
발생** — 그리퍼가 완전히 닫히기 전에 로봇이 상승을 시작해 파지
실패. 이게 5N→10N 결정의 실질적 계기 중 하나. 10N으로 바뀌면서
자연히 완화될 것으로 기대하나[추론], 다음 실측 때 2.0초가 여전히
충분한지 재확인 필요.

PET병(원래 기본값 대상)에 10N을 적용해 시험 삼아 파지 → 문제
없이 성공(참고용, can/paper 결정의 근거는 아님).

 4. 사이클 시간 실측
====================================================================

물체 없이 순수 이동+그리퍼 명령 타이밍만 측정(참고용 하한선):

```
벨트 하강(100mm)                4.492s
닫기+대기(2.0s)                  2.012s
집은 후 상승(100mm)              4.487s
통 상공까지 이동(벨트→CAN_bin)   7.600s
통 PLACE로 하강                  7.200s
열기+대기(1.0s)                  1.009s
놓은 후 상승(100mm)              4.491s
벨트 상공으로 복귀               7.600s
─────────────────────────────────
합계                            38.891s
```

**벨트 왕복 이동(7.6s×2)과 통 하강(7.2s)이 가장 큰 비중** —
사이클 단축이 필요하면 이 세 구간이 1순위 대상. **[전제] 이건
참고용 하한선**이다 — 실제로는 물체 탐지·좌표 계산 시간, 힘
변경 호출 시간(품목이 바뀔 때마다) 등이 추가로 붙는다.

 5. [중요] SAFE 트립의 실제 메커니즘 — 스펙시트에서 확인
====================================================================

OnRobot RG2 User_Manual.pdf(78~79페이지)를 확인했다.

```
Total stroke: 0~110mm (확인)
파지력 조정범위: 3~40N (5/10/40N 전부 유효 범위 안)
```

**핑거팁 러버 패드의 X방향(닫힘축과 수직) 접촉 길이는 매뉴얼에
수치로 없다** — 80페이지 도면은 러버 팁이 아니라 금속 마운팅
브라켓 치수였다. **[전제로 남음] 이 값이 필요하면 직접 실측
(자로 측정)해야 한다.**

**더 중요한 발견**: 79페이지에 명시적 경고가 있다 — "긴 물체를
잡으면 안전스위치가 의도치 않게 작동할 수 있다." 그리고 **파지
폭(w) 대비 허용 물체 높이(h, 핑거팁 끝에서 계산)의 한계 그래프**
가 있다(폭이 넓을수록 허용 높이가 낮아지는 하락 곡선).

**[추론] 이번 세션 내내 "서로 다른 두 원인"으로 취급했던 SAFE
트립("과도한 파지 깊이" vs "기울어진/비대칭 접촉")이 실은 같은
안전스위치 조건 하나의 두 증상일 가능성이 높다.** 둘 다 결국
"핑거팁 기준 유효 높이가 그 폭에서 허용되는 한계를 넘었다"는
같은 조건으로 통합 설명될 수 있다.

**[팀결정 — 5일차] 핑거팁 접촉 길이는 추가 실측 없이 [미확인]으로
남기고, 안전스위치 그래프는 스펙시트에서 눈대중으로 읽은 근사치를
그대로 채택한다** (`config/gripper_profiles.yaml`에 기록):

```
w≈0~10mm  : h≈65~68mm (최대)
w≈20mm    : h≈50mm
w≈30~50mm : h≈48~49mm
w≈60mm    : h≈46mm
w≈80mm    : h≈42mm
w≈100mm   : h≈37~38mm
```

[추론, 그래프 눈대중 판독값이라 정밀 수치는 아님] 이 값을 다음
세션 파지 시퀀스 설계에서 참고 기준으로 사용한다.
