## 1. 구현 완료 요약
====================================================================

- `conveyor_node.py` 신규 — 설계문서 인터페이스명(`/conveyor/
  set_speed`, `/conveyor/stop`, `/conveyor/status`) 그대로 사용.
  **[전제, 의도된 단순화]** 커스텀 `.srv`(float 필드) 생성 인프라가
  이 패키지(순수 `ament_python`, colcon build 자체가 안 되는 상태로
  확인됨)에 없어 `std_srvs/Trigger`로 단순화 — 실사용이 고정
  100steps/sec 하나뿐이라 기능상 손실 없음. 3-1~3-5절 전부 반영:
  워치독 자리는 만들되 기본 비활성화(`conveyor.watchdog_enabled`,
  PC 분리 시 켤 것), 초기상태 항상 STOP, 종료 시 정지(shutdown
  훅), 시리얼 실패해도 2회 재시도 후 에러 로그만(안 죽음).
- `tracking_node._call_conveyor()`를 서비스 호출로 전환 — 시리얼
  포트는 `conveyor_node`만 소유. 재진입 스핀 방지용 전용 executor
  분리(로봇 executor와도 별개, dry_run 무관하게 항상 생성 — 음성
  명령은 dry_run 중에도 들어올 수 있어서).
- **실측**: `conveyor_node`를 실제로 띄운 채 `tracking_node`에서
  START 음성 명령 → 서비스 호출 → 응답까지 약 100ms로 왕복 확인
  (시리얼만 실패, ROS2 통신 자체는 정상). 두 노드를 각각 독립
  프로세스로 띄워서 확인했습니다.
- 팀원 STT가 상시 리스닝으로 확정돼(v58 이후 팀원 답변) PAUSE/
  RESUME도 시연에서 실사용 확정 — `voice_bridge_node`는 이미
  단순 구독 구조라 추가 변경 없음. 숫자 한글 변환은 TTS 연결 후로
  보류(팀결정).

## 2. 요청4 반대의견 — 세 항목 검토 결과
====================================================================

### 2-1. "(d)가 (a)를 무효화하는가" — 부분 동의, 정밀화

**결론부터: 순서 변경(컨베이어 노드 먼저)에는 동의하지만, 이유를
좀 더 정확히 나누면 다음과 같습니다.**

```
상태 전이 로직(IDLE->RUNNING 변수 변경, Pick 게이팅) 자체는
_call_conveyor()가 서브프로세스를 부르든 서비스를 부르든
전혀 영향받지 않는다 -- 실제로 로봇/컨베이어 없이 순수 로직
테스트로 이미 검증 완료(v57에서 보고).

재검증이 필요한 건 "물리적으로 벨트가 실제로 도는가" 쪽입니다
-- 이건 _call_conveyor()의 호출 경로가 바뀌면(서브프로세스->
서비스) 당연히 다시 확인해야 합니다.
```

**그래서 결론은 같습니다** — 컨베이어 노드를 먼저 만들고 그 위에서
"물리적 벨트 응답"을 딱 한 번만 확인하는 게, 두 번(옛 경로 한 번,
새 경로 한 번) 확인하는 것보다 낫습니다. 다만 "상태 전이 자체도
재검증이 필요한가"에는 "아니오, 그 부분은 이미 끝났다"가 정확한
답이라고 생각합니다 — 순서 조정의 근거는 "물리적 검증의 중복
방지"이지 "로직 검증이 무효화돼서"는 아닙니다.

### 2-2. "워치독을 지금 넣는 게 적절한가" — 동의, 단 기본값 조건부

**배관(구독자, 타이머, 파라미터)은 지금 넣는 데 동의합니다** —
나중에 PC를 분리할 때 코드를 안 건드려도 되는 이점이 실제로
있습니다. **다만 기본값은 반드시 비활성화(`watchdog_enabled=
False`)여야 합니다** — 지금은 로봇 PC/관제 PC가 물리적으로 한
대라 `/system/heartbeat`를 아무도 발행하지 않는데, 기본으로 켜
두면 "하트비트가 없다"가 항상 참이 되어 매 실행마다 오탐으로
벨트를 세워버립니다. **이미 이렇게 구현했습니다**(요청2 반영).
PC 분리 시점에 파라미터 하나만 뒤집으면 되는 구조입니다.

### 2-3. "초기 상태를 정지로 두는 것이 맞는가" — 동의, 반론 없음

이건 반론이 없습니다. 노드가 재시작(수동 재시작이든, 크래시 후
자동 재시작이든)됐는데 이전 상태를 복원해서 벨트가 갑자기 돌면
그 순간 옆에 아무도 없을 수 있습니다 — 안전 후퇴가 명백히 맞는
방향입니다. **이미 이렇게 구현했습니다.**
