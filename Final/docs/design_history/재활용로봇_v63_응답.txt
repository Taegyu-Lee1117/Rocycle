====================================================================

1단계: 기능/노드별 브랜치 9개(`feature/tracking-node`,
`conveyor-node`, `voice-node`, `docker`, `config`,
`calibration-data`, `yolo-model`, `tests`, `package-scaffold`,
`docs`)로 나눠 업로드.

2단계: **[팀 피드백] 시연이 임박했는데 브랜치가 여러 개면 어느
조합이 실제로 동작하는지 헷갈리고 병합에 시간을 쓰게 된다는
지적** — 동의해서 9개 브랜치를 **`main`에 전부 병합**(충돌
없이 깨끗하게 완료)해 "지금 동작하는 상태를 가리키는 브랜치"로
확정했습니다.

3단계: **[사용자 지시] 기능/노드별 브랜치는 정리 완료됐으니
삭제, `features/kdy`는 `feature/documents`로 이름 변경**(앞으로
문서 관련 내용·히스토리를 여기 저장할 예정이라고 함) — 전부
반영했습니다.

**최종 상태**: 원격에 `main`(동작하는 통합 브랜치) +
`feature/documents`(문서용, 구 features/kdy) 2개만 남음.
**관제 PC는 항상 `main`만 pull**하면 됩니다.

## 3. Docker 구성 수정 3건 (사용자가 팀 피드백으로 지적, 전부 타당)
====================================================================

### 3-1. conveyor_node는 컨테이너 밖(호스트)에서 실행

v62에서 만든 Docker 체크리스트에 카메라는 있는데 컨베이어가
없다는 지적. `conveyor_node`는 의존성이 가볍고(`std_srvs`만)
시리얼 장치 하나만 쓰므로 컨테이너에 안 넣고 호스트에서 직접
실행하는 걸로 정리했습니다. `tracking_node`(컨테이너 안)는
`/conveyor/set_speed`·`/conveyor/stop`을 ROS2 서비스로 호출할
뿐 시리얼을 직접 안 여니, `--network host`만 있으면 컨테이너
안에서도 호스트의 conveyor_node를 정상 호출합니다.

### 3-2. 캘리브레이션은 이미지에 굽지 않고 볼륨 마운트

**가장 중요한 지적이었습니다.** 원래 Dockerfile이
`COPY rocycle_robot/ /workspace/...`로 config/calib_capture/models
까지 전부 이미지에 구웠는데, 이러면 캘리브레이션 값이 바뀔
때마다(관제 PC 물리 배치 변경, 재캘리브레이션 등) 이미지를 다시
빌드해야 합니다. **코드만 이미지에 굽고, config/calib_capture/
models는 `docker run -v ...:ro`로 런타임 볼륨 마운트**하도록
수정했습니다 — 이제 캘리브레이션 값이 바뀌어도 파일만 바꾸고
컨테이너 재시작하면 됩니다. 볼륨을 안 걸면 노드가 즉시 에러로
죽습니다(v61이 우려한 "조용히 깨짐"과 달리 시끄럽게 죽으므로
오히려 안전한 실패 모드로 판단했습니다).

### 3-3. .gitignore/README.md 위치 확인

`main` 루트에 이미 정상적으로 있는 것 확인 완료 — 옮길 필요
없었습니다.

## 4. 여전히 미검증인 것 (반복 명시)

GPU 없는 PC에서 작업해서 아래는 관제 PC에서 처음 확인해야 합니다:
```
- 이미지 빌드 자체가 되는가(numpy/torch 버전 충돌 없이)
- GPU가 컨테이너 안에서 인식되는가
- --network host로 호스트 conveyor_node와 실제 통신되는가
- 볼륨 마운트한 캘리브레이션이 정상 로드되는가
```
`docker/README.md`에 체크리스트로 정리돼 있습니다.
