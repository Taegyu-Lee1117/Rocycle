 1. 요청1 — 즉시 확인 (5분 검산) 결과
====================================================================

**(1) 배율 일관성 — 확인, 정확히 일정합니다.** 추가 코너 쌍
20개 이상으로 재확인: 인접 칸(25mm 가정) 거리 비율 0.60~0.64,
9칸 떨어진 먼 쌍도 0.60~0.62 — **위치·방향과 무관하게 일정**.
1-1절 판단 기준대로 "고정 배율이 걸려 있다"에 해당합니다.

**(2) 코너0/코너9가 실제 같은 행 9칸 간격 맞음** — 검출 코드로
직접 확인, 요청3의 우려는 해당 없음.

**(3) T_cam2base 카메라 위치 실측 대조** — 베이스-렌즈 거리
실측 95cm vs 계산값 102cm(7% 차이, 정상). 카메라-벨트 높이도
실측(77cm-7.5cm=69.5cm) vs 계산(73cm) 근접. **카메라 위치 자체는
크게 틀리지 않았습니다** — 2-3절 "t 계산이 통째로 어긋난다"는
아니었습니다.

====================================================================
 3. 진짜 원인 2가지
====================================================================

### 3-1. 알고리즘 버그 (별개로 발견, 3일차 초반에 이미 수정)

corecode `eye2hand_calibration.py`의 커스텀 `Calibrate()` AX=XB
솔버가 **가상의 정답 데이터로도 완전히 틀린 값**을 반환했습니다
(회전오차 94°, 위치오차 908mm). `cv2.calibrateHandEye()`로
교체(같은 가상 데이터로 오차 사실상 0 확인). 이건 회전/위치
오차를 만드는 버그였지, 배율 문제의 원인은 아니었습니다(0-2절
말씀대로 강체변환은 거리를 안 바꾸니까요) — 그런데 이걸 고치고도
배율 문제가 그대로 남아서, 별개 원인이 있다는 걸 알 수 있었습니다.

### 3-2. 캘리브레이션 데이터의 깊이 다양성 부족 [진짜 원인]

각 캘리브레이션 샘플에서 "체커보드-그리퍼 오프셋"을 역산해
일관성을 검사하는 방법을 썼습니다(고정된 물리량이니 모든 샘플에서
같은 값이 나와야 함):
```
X 방향: 표준편차 1.9mm  (정상)
Y 방향: 표준편차 1.0mm  (정상)
Z 방향: 표준편차 7.7mm, 최대 28mm 벌어짐  (비정상)
```

12샘플의 **회전 다양성은 충분**(42°)했지만 **깊이(카메라로부터
거리) 범위가 66mm로 좁아서** 깊이축 정확도가 안 잡혔습니다.
이게 벨트처럼 캘리브레이션 샘플 범위 밖·먼 곳에서 증폭돼 나타난
겁니다. 이건 코드 버그가 아니라 **촬영 전략(샘플 분포) 문제**
입니다 — 4절에서 재캘리브레이션을 권하지 않은 이유("코드
문제라면 다시 찍어도 같은 결과")와 정확히 반대되는 케이스였던
셈입니다.

====================================================================
 4. 깊이 다양성을 넓힌 재캘리브레이션 — 실패
====================================================================

z 범위를 340~445mm(105mm)로 넓혀 재촬영했으나, 오프셋 표준편차가
오히려 **악화**(22.7/9.9/56.5mm)됐습니다. 원인: **체커보드를
테이프로 다시 붙일 때마다 물리적 위치가 미묘하게 달라짐** —
마운팅 재현성 자체가 이 정밀도 수준(수 mm)에서는 한계였습니다.
강성 마운트(3D 프린트 지그 등)가 있어야 근본 해결이 될 것 같은데,
오늘은 준비돼 있지 않아 보류했습니다.

====================================================================
 5. [채택] 실측 기반 경험적 보정
====================================================================

원래 캘리브레이션(12샘플, 알고리즘만 수정)으로 되돌리고, **펜
마킹으로 확보한 그라운드트루스 점에 평면 내 유사변환(배율+회전+
평행이동, 4자유도)을 최소자승 피팅**했습니다:

```
5개 점 피팅: RMS 잔차 4.5mm, 최대 8.6mm
배율 1.65배 (0-1절에서 발견한 압축비율 0.61의 역수와 정확히 일치)
회전 0.61도 (아주 작음 — 순수 스케일 문제에 가까웠던 것으로 보임)
```

`rocycle_robot/geometry/belt_correction.py`로 구현, 단위테스트
2건 통과. **추가로 무작위 코너 5곳에서 재검증 — 0~4mm 오차로
재현 확인**(사용자가 직접 실측 보고).

**[전제] 이 보정은 belt_plane 위에서만 검증됐다.** 통 안쪽 등
다른 평면에 쓰려면 그 평면에서 별도로 재보정해야 합니다 — 원인
(캘리브레이션 깊이 다양성 부족)이 평면마다 다른 크기로 나타날
수 있기 때문입니다.
