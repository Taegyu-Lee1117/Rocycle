====================================================================
 요청 1 — recyclable_list 분리안 검증
====================================================================

**v3 구조와 정확히 대응합니다. 채택합니다.** 제가 v6에서 제안했던
"정책 자체를 되묻는" 재배치안보다 이쪽이 명백히 낫습니다 — 자기가
등록한 걸 되묻지 않고, v3의 이진검증/목적지매핑 분리 구조를 그대로
재현하니까요.

**단, 문서 1절의 예시 시나리오에 오류가 하나 있습니다.**

  "여기는 비닐 재활용 안 돼" → recyclable_list에서 plastic_bag 제외
  → 같은 비닐이 재활용통 대신 일반쓰레기로 감

**`plastic_bag`은 이미 PHYSICAL 트리거(파지곤란)로 지정된
품목입니다.** 이 물체는 애초에 PICK을 시도하지 않고 항상 사람에게
넘어가므로, `recyclable_list` 대조 자체가 실행되지 않습니다 —
즉 이 예시로는 recyclable_list 토글이 실제로 시연되지 않습니다.
**recyclable_list 토글의 예시는 다른 품목(예: opaque_container)으로
바꿔야 합니다** — "이 지역은 불투명 용기 재활용 안 돼" → 같은
품목이 (내용물 질문과 무관하게) 항상 general로 감. [추론]

### a) `/policy/decide` 응답 구조

한 번의 서비스 호출 안에서 내부적으로 두 단계를 순차 적용하는
구조를 권장합니다(왕복 늘리지 않음):

```
Req: cycle_id, material_type, condition_state
내부 처리:
  1. condition_state == 오염 → final_class = "general"
  2. condition_state == 깨끗 & material_type ∈ recyclable_list
       → final_class = material_type
  3. condition_state == 깨끗 & material_type ∉ recyclable_list
       → final_class = "general"
  4. destination_bin = destinations[final_class]
Resp: final_class, destination_bin, needs_confirmation
      (destinations[final_class]가 미등록이면 true)
```

`recyclable_list`는 이진 소속 여부라 자체적으로 "미등록" 상태가
없습니다(목록에 없으면 그냥 비재활용으로 확정 — v3 allowlist와
동일한 opt-in 방식). 그래서 `needs_confirmation`은 여전히
destinations 쪽에만 걸립니다.

### b) 발화 구분 — 제한된 문형으로 강제, 파싱 후 에코 확인 필수화

"비닐은 재활용 안 돼"(recyclable_list)와 "플라스틱은 2번 통으로"
(destinations)는 어휘 신호로 구분 가능합니다 — 부정·배제
표현("안 돼/안 된다/제외")은 recyclable_list, 목적지 표현
("~로/~에/~통")은 destinations. 다만 **두 축이 분리되면서 새로
생긴 오인식 위험**(v3의 단일축 allowlist에는 없던 문제)이라,
이 프로젝트가 이미 써온 원칙("제한된 문형 강제 + 등록 전 확인
질문")을 **이 두 축에 한해서는 필수화**할 것을 제안합니다:

```
recyclable_list 변경: "[품목]은 재활용 안 돼/된다" 문형만 인정
  → 파싱 후 "recyclable_list에서 [품목]을 제외했습니다" 에코
destinations 변경: "[품목]은 [통이름]으로" 문형만 인정
  → 파싱 후 "[품목]의 목적지를 [통이름]으로 설정했습니다" 에코
```

### c) "판별불가" — 통합을 권장합니다

`condition_state`에 별도 3번째 라벨("판별불가")을 두는 것과
`confidence_band` 트리거가 **같은 현상(비전이 애매함)을 두 가지
메커니즘으로 중복 처리**하게 됩니다. YOLO에 "판별불가"라는 클래스를
따로 학습시키는 것도 사실상 "낮은 confidence를 라벨로 재포장"하는
셈이라 데이터 부담만 늘고 이득이 없습니다. [추론]

**권장**: `condition_state`는 이진(깨끗/오염) + confidence 점수만
출력. "애매함" 판정은 기존 `confidence_band` 트리거 하나로 통일.
단, `opaque_container`의 질문(`trigger: class_fixed`)은 이것과
**성격이 다르다는 걸 설계 문서에 명시**해야 합니다 — PET병 질문은
"비전이 흐릿해서" 묻는 것이고, 불투명 용기 질문은 "비전이 원리적으로
못 보는 영역이라서" 묻는 것입니다. 이 구분 자체가 발표에서 좋은
설명 포인트입니다(요청4 통합본에 반영).

 요청 2 — 안정화 대기 시간
====================================================================

**3초는 출발점으로 적절하나, 단독으로는 부족합니다. 이중 확인을
추가할 것을 권장합니다.**

3초 안정화 신호와 실제 PICK 동작 시작 사이에는 INSPECT+DECIDE
처리 시간이 끼어듭니다. 그 사이에 손이 다시 트레이 위로 돌아올
수 있습니다(예: 사람이 "어, 이것도 같이"하며 물건을 추가하려는
경우). **1차 안정화 신호(3초)로 INSPECT를 트리거하되, PICK 모션
시작 직전에 같은 안정성 체크를 한 번 더(0.5~1초) 수행**하는
이중 확인을 제안합니다. 새 비전 능력이 필요 없고, 기존 체크
함수를 두 번 호출하는 것뿐이라 구현 비용이 거의 없습니다.

손 검출 클래스를 따로 학습하는 방식은 채택하지 않습니다 — 말씀하신
대로 데이터 부담이 크고, 이중 확인만으로도 실질적 위험(순간적으로
손을 다시 얹는 경우)의 상당 부분을 잡습니다.

또한 이건 마지막 방어선이 아니라는 점도 명시해둘 필요가 있습니다
— 설령 이 체크를 통과해도, 실제 접촉이 발생하면 기존 힘 하드리밋
(emergency_check/HOLD)이 최종 안전망으로 남아 있습니다.

`vision.stabilization_wait_sec: 3.0`로 외부화하고, 5~6일차 실기
테스트로 값을 조정할 것을 권장합니다(고정값이 아니라 튜닝 대상으로
설계 문서에 명시).

 요청 3 — 불투명 용기 품목 확정
====================================================================

**화장품 통(넓적한 원통형 크림통 스타일)을 1순위로 권장합니다.**
세 후보를 표로 비교했습니다.

| | 요구르트병 | 세제통 | 화장품 통 |
|---|---|---|---|
| a) PET병과 실루엣 대비 | **위험** — 둘 다 "원통+목좁아짐" 형태라 사실상 크기 차이로만 구분될 소지(원칙1 위반 위험) | 좋음 — 손잡이가 뚜렷한 비대칭 돌출부 | **가장 좋음** — "짧고 넓은 원통" vs PET병의 "길고 좁은 원통"은 비율(proportion) 자체가 다른 형태라 크기와 무관하게 구분됨 |
| b) 회전 대칭(지그 필요 여부) | 대칭(지그 불필요) | **비대칭**(손잡이 때문에 지그 필요) | 대칭(지그 불필요, 뚜껑 있는 원통이면) |
| c) RG2 개폐폭(110mm) 이내 | 쉬움(30~50mm대) | 제품에 따라 위험 — 대형은 80~100mm대라 소형(여행용) 선정 필요 | 쉬움 — 크림통류는 통상 50~80mm대 |

**화장품 통이 a)와 b) 두 조건을 동시에 만족하는 유일한 후보입니다.**
요구르트병은 b)는 통과하지만 a)에서 원칙1 위반 위험이 있고,
세제통은 a)는 통과하지만 b)에서 지그가 필요해집니다.

권장 사양: 뚜껑 있는 원통형 크림통(예: 로션/크림 용기), 지름
50~80mm대 소형 제품. 손잡이나 비대칭 돌출부가 없는 것으로 선정할 것.

 요청 5 — 반대 의견
====================================================================

**1절(recyclable_list 분리), 2절(종이팩→불투명 용기 교체) 둘 다
반박하지 않습니다.** 둘 다 구조적으로 정확한 수정입니다.

**단, 2절에 대해 하나만 짚어둡니다(반대는 아니고 대비책 제안).**
종이팩이 빠지면서 데모 품목 4종 중 3종(PET병/불투명용기/비닐)이
전부 **플라스틱 계열**이고 캔 하나만 금속입니다. "재활용 분류
로봇"이라는 큰 주제 대비 재질 다양성이 좁아 보일 수 있어, 심사에서
"종이나 유리는요?"라는 질문이 나올 가능성이 있습니다. [추론]

발표 대응 문구를 미리 준비해둘 것을 제안합니다: "이번 데모는
플라스틱/금속 계열에 집중했고, 재질 판정 구조(YOLO+정책 대조)
자체는 종이·유리로도 그대로 확장됩니다." — 실제로 구조가
material_type을 문자열로만 다루는 외부화 원칙(12절) 위에 있어서
이 주장은 사실에 부합합니다.
