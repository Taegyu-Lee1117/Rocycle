## 1. 무엇을 했는가
====================================================================

`ros2/rocycle_robot/docker/`에 3개 파일 신규:
```
Dockerfile      ros:jazzy-ros-base 베이스, numpy<2 고정,
                ultralytics==8.4.140, tracking_node 전체 포함
entrypoint.sh   ROS2 환경 소싱 후 실행
README.md       빌드/실행 명령, GPU 확인 방법, 미확인 체크리스트
```

**tracking_node 전체(검출+추적+예측+로봇제어+상태머신)를 통째로
컨테이너에 담는 방식을 택했습니다.** 설계문서 원안은 검출 전용
노드(`fixed_camera_node`)를 분리하는 구조지만, v58/v59에서 이미
"통째로 이관 먼저, 문제 생기면 그때 쪼갠다"로 정한 것과 같은
이유로 지금 새로 쪼개지 않았습니다 — 검증된 코드를 건드리는
리스크가 시연 임박 시점에 더 크다고 판단했습니다.

**[중요, 정정] Docker가 numpy/cv_bridge 충돌(CLAUDE.md "알려진
함정")을 자동으로 없애주지 않습니다.** 컨테이너 안에서도 똑같이
`numpy<2` 고정 + `opencv-python` pip 미설치 + 시스템
`python3-opencv` 사용 조치가 필요합니다 — Dockerfile에 이미
반영했습니다. Docker의 실익은 이 조합을 호스트의 다른 환경과
분리해서 재현 가능하게 만드는 것이지, 충돌 자체를 없애는 게
아닙니다.

**`--network host` 필수** — ROS2 DDS 디스커버리가 컨테이너 기본
브리지 네트워크에서는 잘 안 됩니다. STT/TTS 팀원 Docker 연동
때와 정확히 같은 문제라 같은 해법을 그대로 적용했습니다.

## 2. [전제, 미검증] 확인 못한 것
====================================================================

**이 PC는 GPU가 없어서 아래를 하나도 검증 못 했습니다:**
```
- 이미지가 실제로 빌드되는가
- GPU가 컨테이너 안에서 인식되는가(torch.cuda.is_available())
- --network host로 호스트의 다른 ROS2 노드와 실제 통신되는가
- 카메라 장치가 컨테이너 안에서 정상 인식되는가
```
`docker/README.md`에 체크리스트로 남겨뒀습니다 — 관제 PC에서
처음 빌드할 때 팀원과 함께 확인이 필요합니다. torch의 CUDA 버전도
`nvidia-smi`로 확인 후 맞춰 넣어야 할 수 있습니다(Dockerfile에
주석으로 표시해둠).

## 3. 함께 반영한 것 — 기계별 설정 분리(v61 요청1)
====================================================================

Docker 작업과 겹치는 김에 v61 요청1(최우선)도 같이 처리했습니다:

- `camera.cam_to_base_path`: 절대경로(`/home/rokey/...`)였던 걸
  **패키지 상대경로**로 변경(`config/tracking.yaml`). YOLO 모델
  경로에 이미 쓰던 `resolve_model_path()`를 재사용 — 이제 계정/
  경로가 달라도(관제 PC든 컨테이너 안이든) 그대로 동작합니다.
  실측 검증 완료(상대경로로 캘리브레이션 정상 로드 확인).
- `conveyor_node`의 `~/bin/conveyor` 경로를 `conveyor.script_path`
  파라미터로 외부화(기본값은 기존 값 유지, 하위호환).

이 둘은 **"문제 자체를 없애는" 방향**(local.yaml 오버라이드 파일을
새로 만드는 대신, 애초에 기계에 안 묶이게 만듦)이라 v61이 제안한
`config/local.yaml` 패턴보다 간단합니다 — 남은 진짜 기계별 값
(카메라 `/dev/video*` 번호, GPU 유무)은 원래도 우리 config 파일
안에 없고 실행 커맨드 인자/Docker 환경변수 수준이라 별도 파일
분리가 필요 없어 보입니다. 이견 있으면 알려주세요.
