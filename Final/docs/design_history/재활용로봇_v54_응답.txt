## 0. 정정 — v53 2절 "threshold 미반영"은 사실이 아니었습니다
====================================================================

v53에서 "config/item_routing.yaml이 아직 30g"라고 지적하셨는데,
확인해보니 **v52 회신을 받고 그 즉시(v53 작성 전) 이미 80g로
반영해뒀던 상태**였습니다. v53이 그 반영 이전 스냅샷을 보고 쓰신
것 같습니다 — 지금은 `threshold_kg: 0.08`로 확정 반영돼 있습니다.
2-1~2-5절 계산·검증 방침은 그대로 유효하니 재검증(빈 캔 5회/든
캔 5회)만 남은 상태입니다.

## 3. 순차 처리 인덱싱 — "블로킹 후 재매칭" 로직 검증 (3절 요청)
====================================================================

3-2절 제안대로 로봇 없이 검증했습니다. 다만 sleep으로 실제 대기
하는 대신, `_match_track`이 (class_name, base_x, now, tracks)만
보고 결정되는 순수 함수라는 점을 이용해 **시간을 직접 주입**하는
방식을 썼습니다(실제 20초를 기다릴 필요 없이 동일한 수학 검증) —
TrackingNode의 실제 `_match_track`/`_new_track` 메서드를 그대로
바인딩해서 썼기 때문에 코드 사본이 아니라 실물과 100% 같은
로직입니다.

```
시나리오 1: can 트랙 confirmed(pending=9) 후 20초 블로킹 시뮬레이션
  → 실제 이동을 반영한 검출 위치로 재매칭 시도
  → PASS: 같은 트랙으로 정확히 재매칭, pending_count는 리셋 없이
    유지(재확인 불필요 효과 확인)

시나리오 2: 게이트(500mm)를 넘는 검출
  → PASS: 새 트랙 생성 판정(기존 트랙에 오매칭 안 됨)

시나리오 3: 다른 클래스(battery) 검출
  → PASS: can 트랙과 매칭 안 됨
```

**[전제] 이건 매칭 알고리즘 자체의 정확성만 검증한 것**입니다 —
실제 카메라 검출 노이즈나 로봇 반응 타이밍까지 반영한 실물
분리 검증(3-1절, 벨트 정지 상태에서 물체 2개를 40cm 간격으로
두고 벨트 가동)은 로봇을 다시 쓸 수 있을 때 진행하겠습니다.

`_match_track`에 디버그 로그도 추가했습니다(매칭 시도마다 예측
위치/검출 위치/거리/게이트 통과 여부, 트랙 생성·소멸 사유) —
다음 실물 테스트에서 로그만으로도 재매칭 여부를 바로 확인할 수
있습니다.

## 4. STT/TTS 인터페이스 확정 + 스텁 노드 (4절 요청)
====================================================================

설계문서(v32, 1840~1846행)를 확인한 결과 인터페이스가 이미
정의돼 있었습니다: 구독 `/voice/stt/text`, 발행 `/voice/tts/say`
(둘 다 `std_msgs/String`).

**중요한 발견**: `intent_classification.py`(`IntentClassifier`)가
이미 **우리 쪽에서** OpenAI로 의도분류까지 하도록 구현돼 있었습니다
— 즉 팀원 STT/TTS 컨테이너가 넘겨야 할 건 "분류된 의도"가 아니라
**STT 원문 텍스트**입니다. (사용자가 이전에 "데이터를 받는 게
맞을지 파일을 넘기는 게 맞을지" 물었을 때 "의도를 받는 쪽"으로
답했었는데, 정확히는 "텍스트를 받는 쪽"이 맞습니다 — 이 자리에서
정정합니다.)

**신규**: `rocycle_robot/voice/voice_bridge_node.py` — `/voice/
stt/text` 구독 → `IntentClassifier.classify()` → `command_mapping.
dispatch()` → tts_response가 있으면 `/voice/tts/say`에 발행.
`OPENAI_API_KEY` 미설정이어도 노드가 죽지 않고 "분류 비활성화,
텍스트만 로그" 모드로 동작하도록 처리(인스턴스화 테스트 완료,
로봇/카메라 불필요). `setup.py`에 콘솔 스크립트 등록.

**아직 없는 것**: 로봇 실행 연동(`command_mapping.dispatch()`
자체가 스텁 — 로그만 남기고 실제 `/conveyor/stop` 등은 호출 안
함). `state_machine_node`가 생기기 전까지는 이 이상 확장하지
않는 게 맞다고 판단했습니다(원칙6, 구현한 것 이상 표현 금지).
