# 핸드오버 실물 재검증 원본 로그 (8일차, 2026-09-08)

`_handoff_item` 릴리즈 판정 재작성 이후 관제PC(MS-03)에서 실기로 돌린
5회분의 **원본 폴링 로그**다. 요약과 결론은 `docs/CLAUDE.md` 안전 절에
있고, 여기는 그 근거가 된 raw 데이터다.

로그를 남긴 이유: 8일차 오전 사고("사람이 안 받았는데 3초 만에 그리퍼가
열려 라벨 페트병 낙하") 때 **로그가 없어 원인을 추정으로만 답해야 했다.**
그 재발을 막으려고 매 폴링(0.3초)마다 좌표/누적변위/수평속도/연속카운트를
전부 남기도록 했고, 이 파일들이 그 결과다.

## 파일

```
01_처짐만_사용자_안받음.log       구 파라미터. 사람이 일부러 안 받음
02_세게당김_구파라미터_실패.log   구 파라미터. 실제로 당겼으나 미감지 -> 실패
03a_자연스럽게_사용자_성공.log     신 파라미터. 인계 성공
04a_자연스럽게_팀원_성공.log       신 파라미터. 다른 사람. 인계 성공
05a_짧게_팀원_성공.log            신 파라미터. 짧게 당김. 인계 성공
analyze_handoff.py                집계 스크립트(아래)
```

`01`/`02`는 **구 파라미터**(`pull_speed_mm_per_s=15.0`, 누적변위가 3D
전체)로 돌린 것이다. `02`가 실패한 게 임계값 재조정의 직접 근거다.
`03a` 이후는 신 파라미터(`3.0`, `-Z` 제외 변위).

## 집계

```bash
python3 analyze_handoff.py 01_*.log 02_*.log 03a_*.log 04a_*.log 05a_*.log
```
회차별로 수평속도 피크/상위5/중앙값, `-Z제외` 누적변위 최대, 기존 3D
변위 최대, 그리고 임의 임계값으로 릴리즈 판정을 **재생**해준다(녹화
데이터에 파라미터를 바꿔 끼워보는 용도 -- 실제로 이걸로 "신 파라미터를
적용했으면 02가 2.73초에 성공했을 것"을 확인한 뒤 실기에 반영했다).

## 로그 읽을 때 주의

- **`speed_horiz`는 순간값이 아니라 폴링 구간(~0.3초) 평균**이다
  (`step_horizontal / dt`). 0.3초보다 짧은 과도 스파이크는 구조적으로
  안 보인다. "순간 최고 속도"를 논할 때 이 한계를 반드시 같이 밝힐 것.
- `total_disp`는 `-Z`(처짐 방향)를 0으로 취급한 값이고, 괄호 안의
  `3d=`가 수정 전 계산식(3D 전체)이다. 01번 로그는 이 수정 이전이라
  `3d=` 필드가 없다 -- 재계산하려면 `analyze_handoff.py`를 쓸 것.
- 릴리즈 시점의 `total_disp`가 임계값을 얼마나 넘겼는지(overshoot)는
  **안전마진이 아니다.** `speed × dt`로 상한이 걸리는 이산 샘플링
  잡음이다(8일차에 이걸 "마진 축소"로 오독했다가 철회한 이력 있음,
  CLAUDE.md 참고).
