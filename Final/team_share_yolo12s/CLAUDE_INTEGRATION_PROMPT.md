# Claude에 전달할 통합 요청문

아래 내용을 기존 로봇 파지 코드와 이 폴더 전체와 함께 Claude에 전달하세요.

---

현재 카메라 영상에서 물체를 판별하고 로봇이 파지하는 프로그램을 사용하고 있습니다. 기존의 로봇 이동, 그리퍼 제어, 카메라-로봇 좌표 변환, 안전 처리 코드는 최대한 유지하고, 영상 인식 부분을 이 폴더의 커스텀 YOLO12s 모델로 교체해 주세요.

요구사항:

1. `detector.py`의 `RecycleDetector`를 사용해 OpenCV 프레임을 검출합니다.
2. 모델 경로는 `models/yolo12s_best.pt`입니다.
3. 모델 클래스 순서는 `battery`, `can`, `paper`, `pet_labeled`, `pet_unlabeled`, `plastic_bag`입니다.
4. `paper`는 최종 시연에서 사용하는 초코 종이상자를 의미합니다.
5. 한 번에 물체 하나만 컨베이어에 투입합니다. 카메라 주변에는 분류 대상 물체를 두지 않으므로 벨트 ROI는 사용하지 않습니다.
6. 위치 변환 후보 픽셀은 `detection.anchor_pixel`을 사용합니다. 이것은 bbox 하단 중앙 부근이며 벨트 평면에 가까운 기준점입니다.
7. 기존 카메라-로봇 좌표 변환 행렬이나 실제 로봇 좌표값을 새로 추정하거나 임의로 만들지 마세요. 기존 코드의 값을 재사용하고, 없다면 필요한 캘리브레이션 정보를 먼저 요청하세요.
8. 같은 물체가 매 프레임 검출되므로 `detect()`가 값을 반환할 때마다 Pick하지 마세요. 동일 클래스가 최소 3프레임 연속 확인되고 Pick Zone에 들어왔으며 아직 처리하지 않은 객체일 때 한 번만 Pick 명령을 보내세요.
9. 물체가 화면에서 사라진 상태가 일정 프레임 지속된 후에만 다음 객체를 받을 수 있도록 객체 잠금을 해제하세요.
10. 처음에는 ROS2 또는 로봇 명령을 실제로 보내지 않는 dry-run 모드를 만들고, 화면에 클래스, confidence, bbox, anchor pixel, Pick 트리거 여부를 표시해 검증하세요.
11. 기존 프로그램 구조를 분석한 뒤 변경되는 파일과 변경 이유를 먼저 설명하고 수정해 주세요.

YOLO 출력 형식:

```python
{
    "class_id": 1,
    "class_name": "can",
    "confidence": 0.93,
    "bbox": [x1, y1, x2, y2],
    "anchor_pixel": [u, v]
}
```

품목별 정책:

- `battery`: 건전지 통
- `can`: 파지 후 무게 측정, 결과에 따라 캔 통 또는 확인 필요 통
- `paper`: 종이 통
- `pet_labeled`: 사람 전달
- `pet_unlabeled`: 플라스틱 통
- `plastic_bag`: 확인 필요 통

먼저 기존 코드에서 Claude/기존 비전 결과를 생성하는 부분, 픽셀을 로봇 좌표로 변환하는 부분, Pick 명령을 실행하는 부분을 각각 찾아 주세요. 그 후 비전 결과 생성 부분만 YOLO12s로 교체하고 나머지는 가능한 한 보존해 주세요.
